Nine pages of parts; this one is the assembled machine. A developer opens a pull request and, some minutes and one approval later, the change is serving production traffic — with a signed image, an audit trail, a canary, and a one-command rollback. Every box in the diagram below is something you have already built in this track or the course; the work of this page is wiring them together and deciding where the trust boundaries go.

The reference architecture

acme/api (app repo) ├── src/ … ├── Dockerfile # multi-stage, non-root (Day 5, Day 41) ├── test.sh ├── .github/workflows/release.yml # or Jenkinsfile └── CODEOWNERS
acme/platform-config (config repo) ├── apps/api/base/ # Deployment→Rollout, Service, Ingress, HPA, probes ├── apps/api/overlays/dev/ # replicas 1, digest ← bumped by CI ├── apps/api/overlays/prod/ # replicas 6, canary Rollout, digest ← bumped by PR ├── argocd/ # root app, projects, ApplicationSet (C9) └── CODEOWNERS # /apps/*/overlays/prod/ @acme/release-managers
Environments
dev and prod here; add staging by adding an overlay. Each is an Argo CD Application generated by the ApplicationSet from C9; dev and prod may be namespaces in one cluster or separate clusters — the pipeline does not change.
Identity of a release
The image digest, written into the overlay. Tags are for humans; the digest is what the kubelet pulls and what the signature covers.
Gates
Tests + scan + signature (automatic) before anything is deployable; merge to dev is automatic; merge to prod requires a CODEOWNERS review; the canary analysis is the last automatic gate.

Hop by hop

  1. Pull request → CI runs tests (and builds without pushing) on the PR. Reviewers see green checks. Nothing touches any cluster.
  2. Merge to main → CI builds the image with BuildKit, tags it sha-9f2e1c3, pushes, records the digest.
  3. Scan and sign → Trivy fails the job on critical CVEs; cosign signs the digest keylessly with the job's OIDC identity (C3); an SBOM is attached.
  4. Bump dev → CI (as a GitHub App, not a personal token) commits the digest into apps/api/overlays/dev.
  5. Argo CD dev → webhook, render, sync: PreSync migration, waves, PostSync smoke test (C8). Slack: "api dev → 9f2e1c3 Healthy".
  6. Promote → a bot opens a PR changing only overlays/prod's digest; CODEOWNERS approve; merge.
  7. Argo CD prod → sync; the Rollout canaries 10 % → analysis → 50 % → pause → promote → 100 % (C9).
  8. Verify → Argo health Healthy, rollout status complete, Prometheus error rate flat, GitHub commit status green on both repos.

The GitHub Actions workflow

# acme/api/.github/workflows/release.yml
name: release
on:
  pull_request:
  push: { branches: [main] }
permissions: { contents: read }
env: { IMAGE: ghcr.io/acme/api }
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: sh test.sh

  build:
    if: github.event_name == 'push'
    needs: test
    runs-on: ubuntu-latest
    permissions: { contents: read, packages: write, id-token: write }     # id-token: keyless signing
    outputs: { digest: ${{ steps.push.outputs.digest }} }
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with: { registry: ghcr.io, username: ${{ github.actor }}, password: ${{ secrets.GITHUB_TOKEN }} }
      - id: meta
        uses: docker/metadata-action@v5
        with: { images: "${{ env.IMAGE }}", tags: "type=sha,format=short" }
      - id: push
        uses: docker/build-push-action@v6
        with: { context: ., push: true, tags: "${{ steps.meta.outputs.tags }}", cache-from: type=gha, cache-to: "type=gha,mode=max", provenance: false }
      - uses: aquasecurity/trivy-action@0.28.0                             # gate: vulnerabilities
        with: { image-ref: "${{ env.IMAGE }}@${{ steps.push.outputs.digest }}", severity: "CRITICAL,HIGH", ignore-unfixed: true, exit-code: "1" }
      - uses: sigstore/cosign-installer@v3
      - run: cosign sign --yes "$IMAGE@${{ steps.push.outputs.digest }}"   # keyless: cert bound to repo+workflow via OIDC
      - uses: anchore/sbom-action@v0
        with: { image: "${{ env.IMAGE }}@${{ steps.push.outputs.digest }}", format: spdx-json, upload-artifact: true }

  bump-dev:
    needs: build
    runs-on: ubuntu-latest
    steps:
      - id: app
        uses: actions/create-github-app-token@v1                            # a GitHub App scoped to platform-config only
        with: { app-id: ${{ vars.CONFIG_APP_ID }}, private-key: ${{ secrets.CONFIG_APP_KEY }}, repositories: platform-config }
      - uses: actions/checkout@v4
        with: { repository: acme/platform-config, token: ${{ steps.app.outputs.token }} }
      - run: |
          set -euo pipefail
          cd apps/api/overlays/dev
          kustomize edit set image "$IMAGE=$IMAGE@$DIGEST"                  # writes images: [{name, digest}]
          git config user.name ci-bot; git config user.email ci@acme.dev
          git commit -am "api dev → ${GITHUB_SHA::7} ($DIGEST)"
          for i in 1 2 3 4 5; do git push && exit 0; git pull --rebase; done; exit 1   # retry on races
        env: { DIGEST: ${{ needs.build.outputs.digest }} }

  promote-prod:                                                            # manual: Actions → Run workflow, or automated after a soak
    if: github.event_name == 'workflow_dispatch'
    runs-on: ubuntu-latest
    steps:
      - run: |
          gh pr create --repo acme/platform-config --title "api prod → $DIGEST" \
            --body "Promotes the digest currently in dev. Dev has been Healthy since $(date -u)." --head "promote/api-${DIGEST:7:7}" --base main
        env: { GH_TOKEN: ${{ steps.app.outputs.token }} }

The Jenkins equivalent

pipeline {
  agent none
  environment { IMAGE = 'ghcr.io/acme/api'; TAG = "sha-${env.GIT_COMMIT.take(7)}" }
  stages {
    stage('Test')  { agent { kubernetes { inheritFrom 'python' } } steps { sh 'sh test.sh' } }
    stage('Build, scan, sign') {
      when { branch 'main' }
      agent { kubernetes { inheritFrom 'kaniko-trivy-cosign' } }
      steps {
        container('kaniko') { sh '/kaniko/executor --context "$WORKSPACE" --destination "$IMAGE:$TAG" --digest-file /tmp/digest' }
        script { env.DIGEST = readFile('/tmp/digest').trim() }
        container('trivy')  { sh 'trivy image --exit-code 1 --severity CRITICAL,HIGH --ignore-unfixed "$IMAGE@$DIGEST"' }
        container('cosign') { withCredentials([file(credentialsId: 'cosign-key', variable: 'KEY')]) { sh 'cosign sign --yes --key "$KEY" "$IMAGE@$DIGEST"' } }
      }
    }
    stage('Bump dev') {
      when { branch 'main' }
      agent { kubernetes { inheritFrom 'git' } }
      steps {
        withCredentials([usernamePassword(credentialsId: 'config-repo-bot', usernameVariable: 'U', passwordVariable: 'P')]) {
          sh '''
            set -euo pipefail
            git clone "https://$U:$P@github.com/acme/platform-config" cfg && cd cfg/apps/api/overlays/dev
            kustomize edit set image "$IMAGE=$IMAGE@$DIGEST"
            git -c user.name=ci-bot -c user.email=ci@acme.dev commit -am "api dev → $TAG ($DIGEST)"
            for i in 1 2 3 4 5; do git push && exit 0; git pull --rebase; done; exit 1
          '''
        }
      }
    }
  }
  post { failure { slackSend channel: '#ci', message: "api ${env.BUILD_URL} FAILED" } }
}
# apps/api/overlays/dev/kustomization.yaml — what the bump commit changes
resources: [../../base]
images:
- name: ghcr.io/acme/api
  digest: sha256:aa11c0ffee…            # ← one line, one commit, one review (for prod)
replicas: [{ name: api, count: 1 }]

Read the bump script again with C1 in mind: it is the "ci.sh" from the first lab, minus the deploy stage. The deploy stage is now a controller. And the retry loop is there because two pipelines can race on main — the same optimistic-concurrency problem the API server solves with resourceVersion (Day 10), solved here with pull --rebase.

Promotion: same digest, different config

Promotion never rebuilds. The digest that soaked in dev is the digest that goes to prod; only the overlay differs (replicas, resources, a canary strategy, hostnames). Because prod's overlay directory is protected by CODEOWNERS and branch protection, "who can deploy to prod" is a GitHub team, and every prod release is a reviewed PR whose diff is one line.

$ git log --oneline -- apps/api/overlays/prod/kustomization.yaml     # the complete prod release history of api
$ git show 3b9f1e2 -- apps/api/overlays/prod/                         # exactly what changed in that release
$ argocd app history api-prod                                         # the same events from Argo CD's side
$ kubectl -n api-prod rollout history rollout/api                     # …and from the workload's side (Argo Rollouts)

# Kyverno ClusterPolicy (Day 38 admission, as a CRD): only signed images from our CI may run in prod namespaces
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata: { name: verify-api-images }
spec:
  validationFailureAction: Enforce
  rules:
  - name: keyless-signature
    match: { any: [{ resources: { kinds: [Pod], namespaces: ["*-prod"] } }] }
    verifyImages:
    - imageReferences: ["ghcr.io/acme/*"]
      mutateDigest: true                       # rewrite tags to digests on admission
      attestors:
      - entries:
        - keyless:
            subject: "https://github.com/acme/api/.github/workflows/release.yml@refs/heads/main"   # the OIDC identity that signed
            issuer: https://token.actions.githubusercontent.com
  - name: no-latest
    match: { any: [{ resources: { kinds: [Pod] } }] }
    validate:
      message: "use an immutable tag or digest"
      pattern: { spec: { containers: [{ image: "!*:latest" }] } }

The signature check closes a loop that started in C3: cosign's keyless mode gets a short-lived certificate for the workflow's OIDC identity, signs the digest, and records it in a transparency log. The admission webhook (Day 38) verifies the chain — the same certificate-and-issuer trust model as Day 31, applied to "which pipeline built this image".

Watching a release

  • CI: run status, the digest in the job summary, Trivy report, cosign log entry.
  • Git: the bump commit (dev) and the promotion PR (prod) — link both back to the app commit in the message.
  • Argo CD: argocd app wait api-prod --health --sync --timeout 900 in a job, or the UI; metrics argocd_app_info{sync_status,health_status} scraped by Prometheus (Day 56) for alerting on Degraded/OutOfSync.
  • Rollout: kubectl argo rollouts get rollout api -n api-prod -w; the AnalysisRun objects hold the measured values.
  • Workload: readiness/liveness (Day 23), error-rate and latency dashboards, logs.
  • Notifications: Argo CD → Slack on sync/health; GitHub commit status on the config repo commit so the PR shows "deployed".

# the hotfix path: same pipeline, faster
$ git checkout -b hotfix/null-check main && … && git push          # PR → tests → merge → build → dev (minutes)
$ gh workflow run release.yml -f promote=true                       # promotion PR → one reviewer → prod canary
# never: kubectl set image in prod. If you must (break-glass), commit the same change to git within the hour so the agent does not "heal" it away.

Under all of this are exit codes and files. Every gate is a process that returns non-zero (L1): a test, trivy --exit-code 1, cosign verify, kubectl rollout status --timeout, a hook Job, an AnalysisRun's successCondition. Every handoff is a file: an image manifest in a registry, a YAML line in git, a Secret in etcd. When a release "mysteriously" stalls, find the process that has not returned and the file that has not changed — set -x, kubectl describe, argocd app get — the toolkit from L10 and Module 12.

Hands-on lab (60 min) — the whole chain on your laptop

You already built every part. Assemble: KIND, Argo CD (C7), the ApplicationSet with dev/prod overlays (C9), Argo Rollouts (C9 optional), a self-hosted GitHub runner (C3) or Jenkins in the cluster (C5), and a local-only "registry" via kind load or ttl.sh.

  1. Config repo: apps/api/{base,overlays/dev,overlays/prod} with a readiness probe, prod as a Rollout with setWeight: 20 → pause: {}, and the ApplicationSet. Apply root.yaml. Both apps Healthy at the current digest.
  2. App repo: the C1 app, the release workflow above with the Trivy/cosign/SBOM steps removed (or kept if you push to a real registry). Point bump-dev at your config repo with a fine-grained PAT stored as a secret.
  3. Change something (the version string), open a PR, watch test run, merge. Watch: build → bump commit → Argo dev OutOfSync → Synced/Progressing → Healthy. Time it.
  4. Promote: run the promotion (or open the PR by hand), merge, watch prod's Rollout pause at 20 %. kubectl argo rollouts promote. Healthy.
  5. Break dev: change CMD to ["false"], merge. Dev goes Degraded; prod is untouched. git revert the bump commit in the config repo; dev heals. Note that the bad image still exists in the registry — harmless.
  6. Break prod: promote the bad digest on purpose. The Rollout's canary Pod crashes; rollouts abort (or the pause never gets promoted); revert the promotion commit. Prod never lost more than the canary share.
  7. Audit: reconstruct what happened from git log on both repos, argocd app history, and kubectl rollout history — without any CI logs. That reconstructability is the point of the whole design.

Key takeaways

  • Two repos, one artifact identity (the digest), one handoff (a commit), one deployer (a controller in the cluster), one gate for prod (a reviewed PR) — and a canary as the last automatic check.
  • CI builds, tests, scans, signs and commits; Argo CD renders, applies, orders (hooks/waves) and reports; Rollouts decides with metrics. No component holds more access than its hop needs.
  • Admission enforces what CI promised: signed digests only. Humans get read access and a Sync button; changes go through git.
  • Every failure stage has a known signal and a known action; most rollbacks are git revert, and the emergency path is documented and reconciled afterwards.
  • All of it is exit codes and files on Linux, reconciled by control loops — the two ideas this whole site has been about.
