The CKA gives you two hours for 15–20 tasks. Typing YAML from memory is how people run out of time. This lesson is the imperative toolbox: the commands that create Deployments, Services and Pods in one line, generate manifests you then tweak, change live objects in place, and — most important — the fixed sequence of commands you run when something is broken.

What you'll learn

  • Creating: run, create deploy/svc/cm/secret/job/cronjob/ns/sa, expose
  • Changing: scale, set image/env/resources, edit, patch, label, annotate, rollout
  • Inspecting: get -o …, describe, logs, exec, port-forward, cp, top, events
  • The troubleshooting ladder and the flags that make kubectl fast

Session setup (do this first, every time)

$ alias k=kubectl
$ export do="--dry-run=client -o yaml"      # k run x --image=nginx $do > x.yaml
$ export now="--force --grace-period=0"     # k delete pod x $now  (instant delete)
$ source <(kubectl completion bash) && complete -o default -F __start_kubectl k
$ kubectl config set-context --current --namespace=<ns>    # when a task lives in one namespace

Vim tip for the exam terminal: ~/.vimrc with set ts=2 sw=2 et so tabs become two spaces and pasted YAML keeps its indentation (:set paste before pasting).

Generate, then edit

Anything the one-liner cannot express (volumes, probes, affinity, multiple containers) you add by generating YAML first: k run web --image=nginx $do > web.yaml, edit, k apply -f web.yaml. Generated files are minimal and correctly indented — far safer than hand-typing.

The troubleshooting ladder

Run these in order and stop when you see the problem. Ninety percent of broken workloads are diagnosed at rung 2 or 3.

  1. k get pods -o wide — what state? Pending (no node / not scheduled), ContainerCreating (pull, volume, CNI), CrashLoopBackOff (app exits), ImagePullBackOff (image name/registry/secret), Error, OOMKilled (in describe), Running but 0/1 READY (readiness probe). Which node? Restart count?
  2. k describe pod — read the Events at the bottom: FailedScheduling (why, exactly: taints, resources, affinity), Failed to pull image, Unhealthy (probe), FailedMount, Back-off restarting. Check Last State: Terminated, Reason, Exit Code.
  3. k logs pod --previous — what did the app say before it died? Missing env var, wrong DB host, permission denied, port in use.
  4. k exec -it pod -- sh — is the config mounted? Can you wget the dependency? What does env show? (No shell? k debug.)
  5. k get svc,endpointslices + k describe svc — for connectivity: does the selector match, are there endpoints, is targetPort right? Test with a busybox Pod.
  6. k get events -A --sort-by=.lastTimestamp and k get nodes / k describe node — cluster-level: node NotReady, pressure conditions, evictions.
  7. On the node — systemctl status kubelet, journalctl -u kubelet, crictl ps/logs (Day 58).
Under the hood · Linux

kubectl is a REST client; every one of these commands is an HTTP call you can watch with kubectl -v=8 get pods. logs, exec, port-forward and cp are the exceptions that reach a node: the API server proxies them to the kubelet's port 10250, which reads the container's log file under /var/log/pods/ or spawns a process inside the container via the CRI. That is why exec can fail when the API server cannot reach the node even though get works — and why the shell toolkit (grep, jq, ss, journalctl) is half of troubleshooting.

CKA exam tip
  • Read the task twice, note the namespace and any exact names/ports, and confirm at the end with a get. Partial credit exists; a wrong namespace scores zero.
  • Never k edit a Pod's immutable fields (image is allowed; most others are not). Get the YAML, delete with $now, re-apply.
  • When a task says "use the existing Pod", prefer k get pod x -o yaml > x.yaml over rebuilding from scratch.

Hands-on lab (15 min)

Break things, then climb the ladder.

$ k create deploy broken --image=nginx:1.99 --replicas=1      # bad tag
$ k get pods; k describe pod -l app=broken | tail -8              # ImagePullBackOff, "manifest unknown"
$ k set image deploy/broken nginx=nginx:1.27 && k rollout status deploy/broken
$ k run crasher --image=busybox --command -- sh -c 'echo starting; exit 1'
$ k get pod crasher -w                                            # CrashLoopBackOff, restarts climbing
$ k logs crasher --previous; k describe pod crasher | grep -A3 'Last State'
$ k expose deploy broken --port=80 --target-port=8080 --name=wrongport
$ k get endpointslices -l kubernetes.io/service-name=wrongport    # endpoints exist, but port 8080 is wrong
$ k patch svc wrongport -p '{"spec":{"ports":[{"port":80,"targetPort":80}]}}'
$ k run t --rm -it --image=busybox:1.36 -- wget -qO- --timeout=2 http://wrongport | head -2
$ k delete deploy broken; k delete pod crasher $now; k delete svc wrongport

Key takeaways

  • Set alias k, $do, $now and the namespace before anything else.
  • run/create/expose for creation; $do > file for anything with extra fields.
  • scale, set image, edit, patch, label change live objects; replace --force for immutable fields.
  • Troubleshoot in order: get → describe (Events) → logs --previous → exec → svc/endpoints → events/nodes → node shell.
