Kubernetes ships with the plumbing for observability — every container's stdout is captured, every kubelet exposes resource metrics, every control-plane component serves Prometheus metrics — and none of the storage. This lesson covers what you get out of the box (kubectl logs, top, events, the metrics endpoints), where those bytes physically live on a node, and how the standard stack (metrics-server, Prometheus, Grafana, a log shipper) plugs into it.

What you'll learn

  • Container logs: where the kubelet writes them, rotation, kubectl logs options, and why apps must log to stdout
  • Node-level logs: kubelet, containerd and control-plane components via journald and /var/log
  • Metrics: metrics-server for top/HPA vs Prometheus for everything else; the /metrics endpoints
  • Events as a signal and their 1-hour retention
  • The cluster-level stack: Prometheus Operator, node-exporter, kube-state-metrics, Grafana, Fluent Bit/Loki

Container logs

$ kubectl logs api-7f9c                              # current container's stdout+stderr
$ kubectl logs api-7f9c -c sidecar --since=10m --timestamps --tail=200
$ kubectl logs api-7f9c --previous                    # the crashed instance's output — CrashLoopBackOff's best friend
$ kubectl logs -l app=api --all-containers --prefix -f   # every pod of a label, streamed, prefixed with pod/container
$ kubectl logs deploy/api                             # a random pod of the deployment
$ kubectl logs job/import; kubectl logs ds/fluent-bit -n logging

Under the hood: the container runtime writes each container's stdout/stderr to a file on the node — /var/log/pods/<ns>_<pod>_<uid>/<container>/0.log (symlinked from /var/log/containers/<pod>_<ns>_<container>-<id>.log) in a JSON/CRI line format with timestamps. The kubelet rotates them (containerLogMaxSize 10Mi, containerLogMaxFiles 5 by default) and serves them over its API when kubectl logs asks. Consequences:

  • Logs live only on that node and only while the Pod exists there. A deleted or rescheduled Pod's logs are gone unless something shipped them.
  • Logs written to files inside the container are invisible to all of this. Log to stdout/stderr, or run a sidecar that tails the file to its own stdout (Day 21).
  • --previous works because the rotated file of the last instance is kept until the next restart.

Node and control-plane logs

# systemd services (the only two on a kubeadm node)
$ sudo journalctl -u kubelet -f                       # follow
$ sudo journalctl -u kubelet --since "10 min ago" -p warning
$ sudo journalctl -u containerd -n 100 --no-pager
# control-plane components are pods → kubectl logs, or on the node:
$ kubectl -n kube-system logs kube-apiserver-cp-1 --tail=50
$ sudo crictl ps -a | grep apiserver; sudo crictl logs <id>       # when the API server itself is down
$ sudo ls /var/log/pods/kube-system_kube-apiserver-cp-1-*/kube-apiserver/   # the raw files
# audit log, if enabled (API server flag --audit-log-path)
$ sudo tail -f /var/log/kubernetes/audit.log | jq -c 'select(.verb=="delete") | {user: .user.username, obj: .objectRef}'

Metrics

metrics-server (resource metrics)

Scrapes every kubelet's /metrics/resource every 15 s; serves current CPU/memory per Pod and node via metrics.k8s.io. In-memory, no history. Feeds kubectl top, HPA and VPA (Day 20).

$ kubectl top nodes
$ kubectl top pods -A --sort-by=cpu | head
$ kubectl top pod api-7f9c --containers

Prometheus (everything, with history)

Pull-based time series database. Scrapes /metrics endpoints: kubelet + cAdvisor (container CPU/memory/network/disk), API server, scheduler, controller-manager, etcd, kube-proxy, CoreDNS, node-exporter (host OS), kube-state-metrics (object state: replicas available, Pod phase, restarts), and your apps. Queried with PromQL; alerts via Alertmanager; dashboards in Grafana.

$ kubectl get --raw /metrics | grep -E '^apiserver_request_total' | head -3         # API server's own metrics
$ kubectl get --raw /api/v1/nodes/worker-1/proxy/metrics/cadvisor | grep container_memory_working_set_bytes | head -3
$ kubectl get --raw /api/v1/nodes/worker-1/proxy/metrics/resource | head              # what metrics-server reads
# kube-prometheus-stack: Prometheus Operator + Grafana + node-exporter + kube-state-metrics + dashboards + alert rules
$ helm install kps prometheus-community/kube-prometheus-stack -n monitoring --create-namespace
$ kubectl -n monitoring port-forward svc/kps-grafana 3000:80        # admin / prom-operator
$ kubectl -n monitoring port-forward svc/kps-kube-prometheus-stack-prometheus 9090

Useful PromQL to know exists: rate(container_cpu_usage_seconds_total{container!=""}[5m]), container_memory_working_set_bytes, kube_pod_container_status_restarts_total, kube_deployment_status_replicas_unavailable, up{job="kubelet"}, etcd_server_has_leader, apiserver_request_duration_seconds. The Prometheus Operator's ServiceMonitor/PodMonitor CRDs (Day 40) tell it what to scrape.

Events

$ kubectl get events --sort-by=.lastTimestamp -A | tail -20
$ kubectl get events --field-selector type=Warning -A
$ kubectl get events --field-selector involvedObject.name=api-7f9c
$ kubectl events --for deploy/api --watch                    # newer subcommand
$ kubectl describe pod api-7f9c | tail -15                   # events are the last section

Events are objects in etcd with a default TTL of 1 hour (--event-ttl) — the reason "it was fine this morning" cannot be investigated from events alone. Ship them (kube-state-metrics exposes counts; the event-exporter / Loki shippers store them) if you need history. Scheduler decisions, image pulls, probe failures, OOM kills, evictions and controller actions all appear here first.

Log shipping

To keep logs beyond a Pod's life, run a DaemonSet agent (Fluent Bit, Vector, Promtail/Alloy, Filebeat) that mounts /var/log/pods and /var/lib/docker/containers (hostPath), tails every file, enriches lines with Pod metadata from the API (namespace, labels, container), and forwards to a store: Loki (queried from Grafana with LogQL), Elasticsearch/OpenSearch (Kibana), or a cloud service (CloudWatch, Cloud Logging). One agent per node covers every Pod — no app changes, no sidecars.

# the shape of every log agent DaemonSet
spec:
  template:
    spec:
      serviceAccountName: fluent-bit          # RBAC: get/list/watch pods, namespaces (for metadata)
      tolerations: [{operator: Exists}]        # every node, including control plane
      containers:
      - name: fluent-bit
        image: fluent/fluent-bit
        volumeMounts:
        - {name: varlog, mountPath: /var/log, readOnly: true}
      volumes:
      - {name: varlog, hostPath: {path: /var/log}}
Under the hood · Linux

All of this is files and sockets: container logs are plain files under /var/log/pods written by containerd's shim (which holds the container's stdout pipe); kubelet/containerd logs go to journald (journalctl reads the binary journal in /var/log/journal); metrics are HTTP text on :10250/metrics, :9100 (node-exporter), :2381 (etcd). When kubectl cannot help — API server down, node unreachable — tail -f /var/log/pods/…, journalctl -u kubelet, crictl logs and curl -sk https://localhost:10250/metrics --cert … on the node still work. du -sh /var/log/pods/* and df -h /var/log find the Pod that filled the disk (DiskPressure).

CKA exam tip
  • Classic: "find the Pod whose log contains ERROR and save the line to a file" → kubectl logs POD | grep ERROR > /path. Know -c, --previous, --all-containers, -l.
  • "Which node/pod uses the most CPU?" → kubectl top nodes / pods --sort-by=cpu (metrics-server is installed in the exam environment).
  • Control plane down → crictl logs and journalctl -u kubelet on the node, not kubectl.
  • Events sorted by time are the fastest way to see what just happened cluster-wide.

Hands-on lab (20 min)

$ kubectl run talker --image=busybox --command -- sh -c 'i=0; while true; do echo "line $i $(date)"; i=$((i+1)); sleep 1; done'
$ kubectl logs talker --tail=3 --timestamps
$ docker exec cka-worker sh -c 'ls /var/log/pods/ | grep talker; tail -2 /var/log/pods/default_talker_*/talker/0.log'   # or the node the pod is on
$ kubectl exec talker -- kill 1; sleep 5; kubectl logs talker --previous --tail=2      # the old instance's log survives one restart
$ kubectl top pod talker 2>/dev/null || echo "install metrics-server (Day 20)"
$ kubectl get --raw /metrics | grep -c '^apiserver_'
$ kubectl get events --sort-by=.lastTimestamp | tail -5
$ docker exec cka-control-plane journalctl -u kubelet -n 5 --no-pager
$ kubectl delete pod talker $now

Key takeaways

  • Container stdout/stderr → files in /var/log/pods on the node → kubectl logs via the kubelet. Node-local, rotated, lost with the Pod unless shipped.
  • kubelet and containerd log to journald; control-plane components are Pods (kubectl logs or crictl logs).
  • metrics-server = now (top, HPA); Prometheus = history and alerting, scraping kubelet/cAdvisor, components, node-exporter, kube-state-metrics.
  • Events explain scheduling, pulls, probes and evictions but expire after 1 hour.
  • Ship logs with a DaemonSet agent to Loki/Elasticsearch; deploy kube-prometheus-stack for metrics and dashboards.
