Not all storage needs to outlive the Pod. Scratch space for a build, a buffer shared between an app and its sidecar, a copy of the Pod's own labels for a config file — these need a volume that appears with the Pod and disappears with it. Kubernetes calls these ephemeral volumes. They share the same volumes/volumeMounts shape as everything else, so learning them here makes PersistentVolumes on Day 27 a small step.

What you'll learn

  • The Pod-level volumes + container-level volumeMounts model
  • emptyDir: lifetime, medium: Memory, sizeLimit, and what survives a container restart
  • downwardAPI: exposing Pod metadata and resources as files or env vars
  • projected volumes and a preview of ConfigMap/Secret volumes
  • Generic ephemeral volumes: a PVC that lives and dies with the Pod

The model: declare at Pod level, mount per container

apiVersion: v1
kind: Pod
metadata:
  name: builder
spec:
  volumes:                         # 1. what volumes exist (Pod scope)
  - name: scratch
    emptyDir: {}
  - name: podinfo
    downwardAPI:
      items:
      - path: labels
        fieldRef: {fieldPath: metadata.labels}
  containers:
  - name: app
    image: myapp
    volumeMounts:                  # 2. where each container sees them
    - name: scratch
      mountPath: /tmp/work
    - name: podinfo
      mountPath: /etc/podinfo
      readOnly: true
  - name: helper
    image: busybox
    volumeMounts:
    - name: scratch
      mountPath: /shared           # same volume, different path
      subPath: helper              # only a subdirectory of it

A volume's type is the one key under it (emptyDir, hostPath, persistentVolumeClaim, configMap, …). subPath mounts a sub-directory or single file; readOnly is per mount; mountPropagation is only for host-mount tricks.

emptyDir

volumes:
- name: cache
  emptyDir:
    sizeLimit: 500Mi        # exceeding it evicts the Pod (counts as ephemeral-storage)
- name: fast
  emptyDir:
    medium: Memory          # tmpfs: RAM-backed, counts against the container's MEMORY limit
    sizeLimit: 64Mi
  • Created empty when the Pod is assigned to a node; deleted when the Pod is removed from that node. Container crashes and restarts do not clear it — that is its main advantage over the container's own filesystem.
  • Lives on the node's disk under /var/lib/kubelet/pods/<pod-uid>/volumes/kubernetes.io~empty-dir/<name>. Node disk fills → DiskPressure → evictions; set sizeLimit.
  • medium: Memory gives a tmpfs. Fast, never touches disk (good for secrets in flight), but every byte counts against the Pod's memory limit and is lost on node reboot.
  • Typical uses: scratch/temp space, shared buffer between containers (Day 21's sidecar log pattern), checkpoints for long computations, disk-backed caches.

downwardAPI

The application often needs to know things about its own Pod — its name, namespace, labels, the node it runs on, its CPU limit for sizing thread pools. Instead of calling the API server (which needs RBAC and a client library), the downward API pushes those values into the container as environment variables or files.

containers:
- name: app
  env:
  - name: POD_NAME
    valueFrom:
      fieldRef: {fieldPath: metadata.name}
  - name: POD_NAMESPACE
    valueFrom:
      fieldRef: {fieldPath: metadata.namespace}
  - name: POD_IP
    valueFrom:
      fieldRef: {fieldPath: status.podIP}
  - name: NODE_NAME
    valueFrom:
      fieldRef: {fieldPath: spec.nodeName}
  - name: CPU_LIMIT
    valueFrom:
      resourceFieldRef:
        containerName: app
        resource: limits.cpu
        divisor: 1m           # → "500" for 500m
  - name: MEM_REQUEST
    valueFrom:
      resourceFieldRef:
        containerName: app
        resource: requests.memory
        divisor: 1Mi
volumes:
- name: podinfo
  downwardAPI:
    items:
    - path: "labels"
      fieldRef: {fieldPath: metadata.labels}
    - path: "annotations"
      fieldRef: {fieldPath: metadata.annotations}
    - path: "cpu_limit"
      resourceFieldRef:
        containerName: app
        resource: limits.cpu
        divisor: 1m
containers:
- name: app
  volumeMounts:
  - name: podinfo
    mountPath: /etc/podinfo
    readOnly: true
# /etc/podinfo/labels →
#   app="web"
#   tier="frontend"

Env vars are set once at container start; files are updated when labels/annotations change (the kubelet re-syncs them, with a short delay). Only a fixed set of fields is available through fieldRef (metadata.name/namespace/uid/labels/annotations, spec.nodeName/serviceAccountName, status.podIP/podIPs/hostIP) — labels and annotations only as volumes, single values only as env.

ConfigMap and Secret volumes (preview)

volumes:
- name: config
  configMap:
    name: app-config
    items: [{key: app.yaml, path: app.yaml}]   # optional: pick keys and rename
- name: creds
  secret:
    secretName: db-creds
    defaultMode: 0400

Each key becomes a file. Like downwardAPI files, they are updated in place when the object changes (unless mounted with subPath, which freezes them). Day 28 goes deep.

projected: several sources, one directory

volumes:
- name: all-in-one
  projected:
    sources:
    - configMap: {name: app-config}
    - secret: {name: db-creds, items: [{key: password, path: db/password}]}
    - downwardAPI:
        items: [{path: labels, fieldRef: {fieldPath: metadata.labels}}]
    - serviceAccountToken:
        path: token
        expirationSeconds: 3600
        audience: vault

This is how the automatic ServiceAccount token is mounted at /var/run/secrets/kubernetes.io/serviceaccount — a projected volume of the token, the cluster CA and the namespace (Day 37).

Generic ephemeral volumes

volumes:
- name: scratch-disk
  ephemeral:
    volumeClaimTemplate:
      spec:
        accessModes: [ReadWriteOnce]
        storageClassName: fast-ssd
        resources: {requests: {storage: 100Gi}}

A real PVC (and CSI-provisioned disk) created with the Pod and deleted with it — for workloads that need more scratch space or IOPS than the node disk offers but no persistence. The PVC is named <pod>-<volume> and owned by the Pod.

Under the hood · Linux

All of these are directories the kubelet prepares under /var/lib/kubelet/pods/<uid>/volumes/<plugin>/<name> and bind-mounts into the container's mount namespace. emptyDir is a plain directory (or a fresh tmpfs mount for medium: Memory). ConfigMap, Secret, downwardAPI and projected volumes are also tmpfs — and the "live update" is implemented with a symlink swap: files live in a timestamped directory ..2024_06_01_10_00_00.123/, with ..data symlinked to it; the kubelet writes the new version into a new directory and atomically repoints ..data. That atomic swap is why subPath mounts (which bind-mount a specific file, bypassing the symlink) never see updates.

$ kubectl exec app -- ls -la /etc/podinfo/     # labels -> ..data/labels, ..data -> ..2024_…
$ kubectl exec app -- df -h /etc/podinfo /tmp/work
# on the node
$ ls /var/lib/kubelet/pods/<uid>/volumes/
CKA exam tip
  • "Share a directory between two containers" → emptyDir, mounted in both. Fastest to type: emptyDir: {}.
  • "Expose the Pod name as an env var" → valueFrom.fieldRef.fieldPath: metadata.name.
  • Volumes are under spec.volumes (Pod) and mounts under spec.containers[].volumeMounts; the names must match exactly — a mismatch fails validation with a clear error.

Hands-on lab (15 min)

$ cat <<EOF | kubectl apply -f -
apiVersion: v1
kind: Pod
metadata: {name: eph, labels: {app: eph, tier: demo}}
spec:
  volumes:
  - {name: scratch, emptyDir: {}}
  - {name: mem, emptyDir: {medium: Memory, sizeLimit: 16Mi}}
  - name: podinfo
    downwardAPI:
      items: [{path: labels, fieldRef: {fieldPath: metadata.labels}}]
  containers:
  - name: app
    image: busybox:1.36
    command: ['sh','-c','echo started >> /scratch/log; sleep 3600']
    env:
    - {name: POD_NAME, valueFrom: {fieldRef: {fieldPath: metadata.name}}}
    - {name: NODE, valueFrom: {fieldRef: {fieldPath: spec.nodeName}}}
    volumeMounts: [{name: scratch, mountPath: /scratch}, {name: mem, mountPath: /mem}, {name: podinfo, mountPath: /etc/podinfo}]
EOF
$ kubectl exec eph -- sh -c 'env | grep -E "POD_NAME|NODE"; cat /etc/podinfo/labels; df -h /mem /scratch'
$ kubectl exec eph -- kill 1; sleep 5; kubectl get pod eph          # container restarted (RESTARTS 1)
$ kubectl exec eph -- cat /scratch/log                               # two "started" lines: emptyDir survived the restart
$ kubectl label pod eph tier=changed --overwrite; sleep 70; kubectl exec eph -- cat /etc/podinfo/labels   # file updated
$ kubectl delete pod eph $now                                        # emptyDir gone with the Pod

Key takeaways

  • spec.volumes declares; volumeMounts attaches per container by name and path.
  • emptyDir lives as long as the Pod is on the node; survives container restarts; medium: Memory = tmpfs counted against memory limits.
  • downwardAPI injects Pod metadata/resources as env (static) or files (live-updated).
  • ConfigMap, Secret, downwardAPI and SA tokens can be combined in one projected volume.
  • Live updates work via an atomic symlink swap; subPath mounts never update.
