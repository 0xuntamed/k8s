Time to run it. NGINX Gateway Fabric (NGF) is the NGINX project's Gateway API implementation: a controller that watches Gateways and routes and programs an nginx data plane. This lesson installs the Gateway API CRDs and NGF on KIND, creates a Gateway, and works through the HTTPRoute features that Ingress could not do cleanly — path and header matching, traffic splitting, header modification, redirects — verifying each with curl.

What you'll learn

  • Installing the Gateway API CRDs (standard channel) and NGF, and exposing its Service
  • Creating a Gateway and reading its status
  • HTTPRoute matching: PathPrefix vs Exact, header and query matches, precedence
  • Traffic splitting with weights (canary) and RequestMirror
  • Filters: RequestHeaderModifier, RequestRedirect, URLRewrite
  • Debugging with route status conditions and NGF logs

Install

# 1. Gateway API CRDs — versioned separately from any implementation
$ kubectl kustomize "https://github.com/nginx/nginx-gateway-fabric/config/crd/gateway-api/standard?ref=v1.6.0" | kubectl apply -f -
$ kubectl get crd | grep gateway.networking.k8s.io      # gatewayclasses, gateways, httproutes, grpcroutes, referencegrants
# 2. NGF itself (controller + nginx data plane in one Deployment)
$ helm install ngf oci://ghcr.io/nginx/charts/nginx-gateway-fabric --create-namespace -n nginx-gateway \
    --set service.type=NodePort --set service.nodePorts.http=30080     # KIND: reuse the Day 8 port mapping
$ kubectl -n nginx-gateway get pods,svc
$ kubectl get gatewayclass                               # nginx  ACCEPTED True

A Gateway

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: main
  namespace: default
spec:
  gatewayClassName: nginx
  listeners:
  - name: http
    port: 80
    protocol: HTTP
    allowedRoutes:
      namespaces: {from: All}
$ kubectl apply -f gateway.yaml
$ kubectl get gateway main
NAME   CLASS   ADDRESS   PROGRAMMED   AGE
main   nginx             True         10s
$ kubectl describe gateway main | grep -A12 'Listeners:'   # Attached Routes: 0, conditions Accepted/Programmed/ResolvedRefs

Backends

$ kubectl create deploy web --image=nginx --port=80 && kubectl expose deploy web --port=80
$ kubectl create deploy api-v1 --image=hashicorp/http-echo --port=5678 -- -text="api v1" && kubectl expose deploy api-v1 --port=5678
$ kubectl create deploy api-v2 --image=hashicorp/http-echo --port=5678 -- -text="api v2" && kubectl expose deploy api-v2 --port=5678

Routes, feature by feature

1 · Path matching

apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: shop
spec:
  parentRefs: [{name: main}]
  hostnames: [shop.local]
  rules:
  - matches:
    - path: {type: PathPrefix, value: /api}
    backendRefs: [{name: api-v1, port: 5678}]
  - matches:
    - path: {type: Exact, value: /health}
    backendRefs: [{name: api-v1, port: 5678}]
  - matches:
    - path: {type: PathPrefix, value: /}
    backendRefs: [{name: web, port: 80}]
$ kubectl apply -f route.yaml && kubectl get httproute shop        # HOSTNAMES shop.local, PARENTS main
$ curl -s -H 'Host: shop.local' localhost:30080/api               # api v1
$ curl -s -H 'Host: shop.local' localhost:30080/api/orders        # api v1 (PathPrefix)
$ curl -s -H 'Host: shop.local' localhost:30080/apix | head -1    # nginx page: /apix is NOT under /api (segment-aware prefix)
$ curl -s -H 'Host: shop.local' localhost:30080/ | grep -o '<title>.*'

2 · Header and query matching

  rules:
  - matches:
    - path: {type: PathPrefix, value: /api}
      headers: [{name: X-Version, value: v2}]      # AND: path AND header
    backendRefs: [{name: api-v2, port: 5678}]
  - matches:
    - path: {type: PathPrefix, value: /api}
      queryParams: [{name: beta, value: "true"}]
    backendRefs: [{name: api-v2, port: 5678}]
  - matches:
    - path: {type: PathPrefix, value: /api}
    backendRefs: [{name: api-v1, port: 5678}]
$ curl -s -H 'Host: shop.local' -H 'X-Version: v2' localhost:30080/api     # api v2
$ curl -s -H 'Host: shop.local' 'localhost:30080/api?beta=true'            # api v2
$ curl -s -H 'Host: shop.local' localhost:30080/api                        # api v1 — the more specific matches win regardless of order

3 · Traffic splitting (canary)

  rules:
  - matches: [{path: {type: PathPrefix, value: /api}}]
    backendRefs:
    - {name: api-v1, port: 5678, weight: 90}
    - {name: api-v2, port: 5678, weight: 10}
$ for i in $(seq 1 20); do curl -s -H 'Host: shop.local' localhost:30080/api; done | sort | uniq -c    # ~18 v1, ~2 v2
# promote: swap weights, then remove v1. No Deployment rollout involved; both versions run side by side.

4 · Filters: headers, redirect, rewrite, mirror

  rules:
  - matches: [{path: {type: PathPrefix, value: /api}}]
    filters:
    - type: RequestHeaderModifier
      requestHeaderModifier:
        set: [{name: X-Env, value: dev}]
        add: [{name: X-Trace, value: gw}]
        remove: [Cookie]
    - type: ResponseHeaderModifier
      responseHeaderModifier:
        add: [{name: X-Served-By, value: ngf}]
    - type: RequestMirror                       # copy requests to another service; responses discarded
      requestMirror:
        backendRef: {name: api-v2, port: 5678}
    backendRefs: [{name: api-v1, port: 5678}]
  - matches: [{path: {type: PathPrefix, value: /legacy}}]
    filters:
    - type: URLRewrite
      urlRewrite:
        path: {type: ReplacePrefixMatch, replacePrefixMatch: /api}   # /legacy/x → /api/x
    backendRefs: [{name: api-v1, port: 5678}]
  - matches: [{path: {type: PathPrefix, value: /old}}]
    filters:
    - type: RequestRedirect
      requestRedirect: {scheme: https, hostname: shop.example.com, statusCode: 301}
$ curl -si -H 'Host: shop.local' localhost:30080/api | grep -i x-served-by
$ curl -s -H 'Host: shop.local' localhost:30080/legacy/x           # rewritten to /api/x → api v1
$ curl -sI -H 'Host: shop.local' localhost:30080/old | grep -iE 'HTTP|location'   # 301 Location: https://shop.example.com/old
$ kubectl logs deploy/api-v2 --tail=5                              # mirrored requests arriving

Debugging

$ kubectl get httproute shop -o jsonpath='{range .status.parents[*]}{.parentRef.name}{": "}{range .conditions[*]}{.type}={.status}({.reason}) {end}{"\n"}{end}'
main: Accepted=True(Accepted) ResolvedRefs=True(ResolvedRefs)
# Accepted=False  NotAllowedByListeners / NoMatchingListenerHostname / NoMatchingParent
# ResolvedRefs=False  BackendNotFound / RefNotPermitted (needs ReferenceGrant) / InvalidKind
$ kubectl get gateway main -o jsonpath='{.status.listeners[*].attachedRoutes}{"\n"}'
$ kubectl -n nginx-gateway logs deploy/ngf-nginx-gateway-fabric -c nginx-gateway --tail=30
$ kubectl -n nginx-gateway exec deploy/ngf-nginx-gateway-fabric -c nginx -- nginx -T | grep -A5 'server_name shop.local'   # the generated nginx config
Same machinery, better API

NGF is doing exactly what ingress-nginx does — watch objects, write an nginx.conf, reload — but the objects it watches describe intent precisely enough that Envoy Gateway or a cloud LB would do the same thing from the same YAML. Compare the canary above with the ingress-nginx way: a second Ingress with nginx.ingress.kubernetes.io/canary: "true" and canary-weight: "10" annotations that mean nothing to any other controller.

CKA exam tip
  • Likely tasks: create a Gateway of a given class with an HTTP listener; create an HTTPRoute to a Service with a path match; add a second backend with weights. Verify: get gateway PROGRAMMED, get httproute shows the parent, describe httproute conditions.
  • Field names to get right: parentRefs, hostnames, rules[].matches[].path.type/value, backendRefs[].name/port/weight. kubectl explain httproute.spec.rules is available.
  • The CRDs must be installed for kubectl explain to know the kind — exam clusters that ask about Gateway API will have them.

Hands-on lab (25 min)

# run the install, gateway, backends and route sections above on KIND, then:
$ kubectl apply -f - <<EOF
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: {name: shop}
spec:
  parentRefs: [{name: main}]
  hostnames: [shop.local]
  rules:
  - matches: [{path: {type: PathPrefix, value: /api}, headers: [{name: X-Version, value: v2}]}]
    backendRefs: [{name: api-v2, port: 5678}]
  - matches: [{path: {type: PathPrefix, value: /api}}]
    filters: [{type: ResponseHeaderModifier, responseHeaderModifier: {add: [{name: X-Served-By, value: ngf}]}}]
    backendRefs: [{name: api-v1, port: 5678, weight: 80}, {name: api-v2, port: 5678, weight: 20}]
  - matches: [{path: {type: PathPrefix, value: /}}]
    backendRefs: [{name: web, port: 80}]
EOF
$ kubectl get httproute shop; kubectl describe httproute shop | grep -A4 Conditions
$ for i in $(seq 1 10); do curl -s -H 'Host: shop.local' localhost:30080/api; done | sort | uniq -c
$ curl -s -H 'Host: shop.local' -H 'X-Version: v2' localhost:30080/api
$ curl -si -H 'Host: shop.local' localhost:30080/api | grep -i served
# break it: point at a missing service and read the condition
$ kubectl patch httproute shop --type=json -p '[{"op":"replace","path":"/spec/rules/2/backendRefs/0/name","value":"nope"}]'
$ kubectl get httproute shop -o jsonpath='{.status.parents[0].conditions[?(@.type=="ResolvedRefs")]}{"\n"}'   # BackendNotFound
$ curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: shop.local' localhost:30080/                            # 500 from the gateway
$ kubectl delete httproute shop gateway main; kubectl delete deploy web api-v1 api-v2; kubectl delete svc web api-v1 api-v2

Key takeaways

  • Install the Gateway API CRDs, then an implementation (NGF); the GatewayClass appears; a Gateway provisions a listener; routes attach.
  • HTTPRoute matches: PathPrefix (segment-aware), Exact, headers, query, method — specific beats general by spec, not by order.
  • Weighted backendRefs give canaries without annotations; filters modify headers, redirect, rewrite and mirror.
  • Route status conditions (Accepted, ResolvedRefs) explain every failure; the generated nginx config is inspectable.
