Everything so far ran on KIND. Now you build the real thing: three Linux VMs, the kernel prepared, containerd installed, and kubeadm bootstrapping a control plane and joining workers, with Calico as the CNI. Every step is something a managed service hides from you and something the CKA expects you to do or fix. By the end you will know exactly which files, services and sysctls a "node" consists of.

What you'll learn

  • Node prerequisites: swap, kernel modules, sysctls, container runtime, cgroup driver
  • Installing kubeadm, kubelet, kubectl with held versions
  • kubeadm init: what it generates (certs, kubeconfigs, static Pods, bootstrap tokens) and the flags that matter
  • Installing Calico and why nodes are NotReady until you do
  • kubeadm join and the token/CA-hash handshake; verifying the cluster

Step 1 — Prepare every node

# hostnames (each node its own)
$ sudo hostnamectl set-hostname cp-1
# swap off — the kubelet refuses to start with swap enabled (memory accounting)
$ sudo swapoff -a && sudo sed -i '/ swap / s/^/#/' /etc/fstab
# kernel modules for containers and bridged networking
$ cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
$ sudo modprobe overlay && sudo modprobe br_netfilter
# sysctls: let iptables see bridged traffic (Service/NetworkPolicy rules) and forward packets between pods
$ cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
$ sudo sysctl --system
$ lsmod | grep -E 'overlay|br_netfilter'; sysctl net.ipv4.ip_forward

Step 2 — Container runtime (containerd)

$ sudo apt-get update && sudo apt-get install -y containerd      # or Docker's repo for a newer version
$ sudo mkdir -p /etc/containerd && containerd config default | sudo tee /etc/containerd/config.toml > /dev/null
# cgroup driver MUST match the kubelet's (systemd on modern kubeadm)
$ sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
$ sudo systemctl restart containerd && sudo systemctl enable containerd
$ sudo ctr version; ls -l /run/containerd/containerd.sock
The cgroup driver mismatch

If containerd uses cgroupfs while the kubelet uses systemd (the default since 1.22), the node will look fine for minutes and then flap NotReady with kubelet errors about cgroups. SystemdCgroup = true in the runc.options section of config.toml is the single most common thing to check on a hand-built node. See cgroups.

Step 3 — kubeadm, kubelet, kubectl

$ sudo apt-get install -y apt-transport-https ca-certificates curl gpg
$ curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.31/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
$ echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.31/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
$ sudo apt-get update && sudo apt-get install -y kubelet kubeadm kubectl
$ sudo apt-mark hold kubelet kubeadm kubectl                     # upgrades are deliberate (Day 55)
$ sudo systemctl enable --now kubelet                            # it will crash-loop until kubeadm configures it — expected
$ kubeadm version -o short

The repo path pins a minor version (v1.31); patch versions come from apt-get install kubeadm=1.31.2-1.1. All nodes should run the same versions; the kubelet may be up to three minors behind the API server, never ahead.

Step 4 — kubeadm init on the control plane

$ sudo kubeadm init \
    --apiserver-advertise-address=192.168.56.10 \    # the IP other nodes will use (first NIC is often NAT on VirtualBox — be explicit)
    --pod-network-cidr=192.168.0.0/16 \              # must match the CNI's expectation (Calico default)
    --control-plane-endpoint=cp-1 \                  # a stable name; lets you add control planes / an LB later
    --kubernetes-version=v1.31.2
…
Your Kubernetes control-plane has initialized successfully!

You should now deploy a pod network to the cluster…
Then you can join any number of worker nodes by running the following on each as root:
kubeadm join cp-1:6443 --token abcdef.0123456789abcdef --discovery-token-ca-cert-hash sha256:1234…

What just happened, in order (kubeadm init --dry-run or -v=5 shows it):

  1. preflight — checks swap, ports, modules, runtime, versions. Fix warnings; errors abort.
  2. certs — generates the three CAs and every certificate from Day 33 in /etc/kubernetes/pki, with SANs including the advertise address and the control-plane endpoint.
  3. kubeconfig — admin.conf, super-admin.conf, kubelet.conf, controller-manager.conf, scheduler.conf.
  4. kubelet-start — writes /var/lib/kubelet/config.yaml and restarts the kubelet, which now has something to do.
  5. control-plane + etcd — static Pod manifests into /etc/kubernetes/manifests; the kubelet starts them (Day 15).
  6. wait-control-plane — polls /healthz until the API server answers.
  7. upload-config / upload-certs — stores the kubeadm and kubelet config as ConfigMaps in kube-system so join and upgrade can read them.
  8. mark-control-plane — labels the node and adds the node-role.kubernetes.io/control-plane:NoSchedule taint.
  9. bootstrap-token — creates a 24-hour token and RBAC so joining nodes can fetch the CA and request kubelet certificates.
  10. addons — deploys CoreDNS and the kube-proxy DaemonSet.
$ mkdir -p $HOME/.kube && sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config && sudo chown $(id -u):$(id -g) $HOME/.kube/config
$ kubectl get nodes                       # cp-1 NotReady — no CNI yet
$ kubectl get pods -n kube-system         # coredns Pending; everything else Running
$ ls /etc/kubernetes /etc/kubernetes/manifests /etc/kubernetes/pki

Step 5 — Install Calico

$ kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.28.0/manifests/tigera-operator.yaml
$ curl -O https://raw.githubusercontent.com/projectcalico/calico/v3.28.0/manifests/custom-resources.yaml
$ grep cidr custom-resources.yaml            # 192.168.0.0/16 — must equal --pod-network-cidr; edit if different
$ kubectl create -f custom-resources.yaml
$ watch kubectl get pods -n calico-system    # calico-node, calico-kube-controllers, csi… all Running
$ kubectl get nodes                          # cp-1 Ready
$ kubectl get pods -n kube-system            # coredns now Running

The Calico operator installs a DaemonSet that drops the CNI binaries into /opt/cni/bin and the config into /etc/cni/net.d on every node, then runs the calico-node agent that programs routes (BGP or VXLAN) and NetworkPolicies. The kubelet notices the CNI config and flips the node to Ready (Day 25).

Step 6 — Join the workers

# on cp-1, if you lost the join command or the token expired (24 h):
$ kubeadm token create --print-join-command
# on each worker, as root:
$ sudo kubeadm join cp-1:6443 --token abcdef.0123456789abcdef --discovery-token-ca-cert-hash sha256:1234…
# back on cp-1:
$ kubectl get nodes -o wide                  # all Ready within a minute
$ kubectl label node worker-1 node-role.kubernetes.io/worker=   # cosmetic ROLES column

The join handshake: the worker connects to the API server with the bootstrap token, downloads the cluster-info ConfigMap from kube-public, verifies the CA against the --discovery-token-ca-cert-hash (so a MITM cannot hand it a fake CA), then submits a CSR for its kubelet client certificate, which the controller-manager auto-approves for bootstrap tokens. The kubelet writes /etc/kubernetes/kubelet.conf pointing at its new cert and starts reporting (Day 34). If the hash is omitted (--discovery-token-unsafe-skip-ca-verification), the CA is trusted blindly.

Verify

$ kubectl get nodes,pods -A -o wide
$ kubectl create deploy web --image=nginx --replicas=3 && kubectl expose deploy web --port=80 --type=NodePort
$ kubectl get pods -o wide                   # spread across workers, pod IPs from 192.168.x.x
$ curl http://192.168.56.11:$(kubectl get svc web -o jsonpath='{.spec.ports[0].nodePort}')
$ kubectl run t --rm -it --image=busybox:1.36 -- nslookup web      # DNS works
$ sudo kubeadm certs check-expiration        # one year from today
Under the hood · Linux

After this lesson you can list what a Kubernetes node is: a kernel with overlay and br_netfilter loaded and ip_forward on; containerd.service owning /run/containerd/containerd.sock and /var/lib/containerd (image layers, OverlayFS snapshots); kubelet.service reading /var/lib/kubelet/config.yaml and /etc/kubernetes/kubelet.conf, with a drop-in at /usr/lib/systemd/system/kubelet.service.d/10-kubeadm.conf that passes /var/lib/kubelet/kubeadm-flags.env; CNI binaries in /opt/cni/bin and config in /etc/cni/net.d; certificates in /etc/kubernetes/pki (control plane) and /var/lib/kubelet/pki (every node); Pod directories under /var/lib/kubelet/pods; logs in /var/log/pods and the journal. Every troubleshooting command on Days 57–58 targets one of these.

CKA exam tip
  • The exam rarely asks for a full init, but often for a join: kubeadm token create --print-join-command on the control plane, run it on the worker.
  • Know the preflight items by heart — swap, ip_forward, br_netfilter, containerd running, cgroup driver — because "make this node join / become Ready" questions are one of them broken.
  • Know the file locations: manifests, pki, kubelet config, CNI dirs, kubeconfigs in /etc/kubernetes.
  • Version skew: kubelet ≤ API server; kubectl within ±1 minor.

Hands-on lab (60–90 min)

Build the three-node cluster above. Then break and observe:

$ sudo swapon -a && sudo systemctl restart kubelet && journalctl -u kubelet -n 5     # "running with swap on is not supported"
$ sudo swapoff -a && sudo systemctl restart kubelet
$ sudo sysctl -w net.ipv4.ip_forward=0                          # pod-to-pod traffic across nodes stops; kubelet warns in preflight-style checks
$ sudo sysctl -w net.ipv4.ip_forward=1
$ sudo mv /etc/cni/net.d/10-calico.conflist /tmp/ && sleep 60 && kubectl get nodes   # node NotReady: "cni plugin not initialized"
$ sudo mv /tmp/10-calico.conflist /etc/cni/net.d/
$ kubeadm token list; kubeadm token create --ttl 1h --print-join-command
$ sudo kubeadm reset -f    # on a worker: undo the join (then rejoin) — do this last

Key takeaways

  • Node prep: hostname, swap off, overlay + br_netfilter, ip_forward + bridge-nf sysctls, containerd with SystemdCgroup = true, held kube* packages.
  • kubeadm init generates PKI, kubeconfigs, kubelet config, static Pods, bootstrap token and add-ons; the node stays NotReady until a CNI is installed.
  • Calico's Pod CIDR must match --pod-network-cidr.
  • kubeadm join uses a bootstrap token + CA hash to fetch the CA and get a kubelet certificate via CSR.
  • A node is: kernel settings + containerd + kubelet (systemd) + CNI files + certificates + /var/lib/kubelet.
