A Deployment answers "keep N copies running". Two other questions need their own controllers: "run one copy on every node" (a DaemonSet — agents, CNI, kube-proxy, log shippers) and "run this until it finishes, retrying if it fails" (a Job, and on a schedule, a CronJob). They share the Pod template and label-selector machinery you already know; what differs is what "desired state" means.

What you'll learn

  • DaemonSet: one Pod per (matching) node, tolerations, update strategy, and how it differs from a Deployment
  • Job: completions, parallelism, backoffLimit, restartPolicy, activeDeadlineSeconds, TTL, indexed jobs
  • CronJob: schedule syntax, concurrencyPolicy, startingDeadlineSeconds, history limits, suspend
  • Running a CronJob by hand and the common failure modes

DaemonSet

apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: node-exporter
  namespace: monitoring
spec:
  selector:
    matchLabels: {app: node-exporter}
  updateStrategy:
    type: RollingUpdate            # or OnDelete (new pods only when you delete old ones)
    rollingUpdate:
      maxUnavailable: 1            # nodes updated at a time (maxSurge also allowed)
  template:
    metadata:
      labels: {app: node-exporter}
    spec:
      tolerations:                 # run on control-plane nodes too
      - key: node-role.kubernetes.io/control-plane
        operator: Exists
        effect: NoSchedule
      nodeSelector:                # optional: only a subset of nodes
        kubernetes.io/os: linux
      hostNetwork: true            # agents often need the node's network/PID/paths
      hostPID: true
      containers:
      - name: exporter
        image: prom/node-exporter
        ports: [{containerPort: 9100, hostPort: 9100}]
        volumeMounts:
        - {name: proc, mountPath: /host/proc, readOnly: true}
      volumes:
      - name: proc
        hostPath: {path: /proc}
  • No replicas: the count is "number of nodes that match nodeSelector/affinity and whose taints are tolerated". Add a node → a Pod appears; remove it → gone.
  • Since 1.12 the default scheduler places DaemonSet Pods (via node affinity injected by the controller), so they respect resources and can be Pending like anything else. They also get automatic tolerations for not-ready, unreachable, disk-pressure, memory-pressure, pid-pressure, unschedulable — so they run even on cordoned or pressured nodes.
  • Rolling updates go node by node; kubectl rollout status/history/undo ds/… work.
  • Typical residents of kube-system: kube-proxy, the CNI agent, CSI node plugin, node-exporter, Fluent Bit, security agents.
$ kubectl get ds -A                     # DESIRED CURRENT READY UP-TO-DATE AVAILABLE NODE SELECTOR
$ kubectl create deploy x --image=busybox $do | sed 's/Deployment/DaemonSet/;/replicas/d;/strategy/d' | kubectl apply -f -   # no "create ds"; convert a deployment
$ kubectl rollout restart ds/node-exporter -n monitoring

Job

apiVersion: batch/v1
kind: Job
metadata:
  name: import
spec:
  completions: 5              # total successful pods needed (default 1)
  parallelism: 2              # how many may run at once (default 1)
  backoffLimit: 4             # failed pods before the Job is marked Failed (default 6)
  activeDeadlineSeconds: 600  # kill everything after 10 min regardless
  ttlSecondsAfterFinished: 3600   # garbage-collect the Job (and its pods) 1 h after it finishes
  completionMode: Indexed     # optional: each pod gets JOB_COMPLETION_INDEX 0..N-1
  template:
    spec:
      restartPolicy: OnFailure    # REQUIRED: OnFailure or Never (never Always)
      containers:
      - name: import
        image: myimporter:1.4
        command: ["./import", "--shard=$(JOB_COMPLETION_INDEX)"]
restartPolicy: OnFailure
The kubelet restarts the failed container in the same Pod (back-off applies). Each restart counts toward backoffLimit.
restartPolicy: Never
A failed Pod stays (for its logs) and the Job controller creates a new Pod. Easier to debug; more Pods lying around.
completions / parallelism
Omit both → run one Pod to success. completions: N → N successes (queue-style). parallelism: P alone with no completions → "work queue" mode: Pods run until any one succeeds… actually until all running Pods exit successfully once one has — use with apps that pull from a queue.
Indexed
Static sharding: each Pod knows its index (env var and annotation) and processes its slice; a failed index is retried with the same index.
podFailurePolicy
Fine-grained: "exit code 42 → fail the Job immediately", "evicted by node drain → do not count against backoffLimit".
suspend: true
Create the Job without starting it; flip to false to launch (used by queueing systems like Kueue).
$ kubectl create job hello --image=busybox -- echo hello
$ kubectl get jobs -w                     # COMPLETIONS 0/1 → 1/1, DURATION
$ kubectl get pods -l job-name=hello      # Completed
$ kubectl logs job/hello
$ kubectl describe job hello | grep -E 'Pods Statuses|Events' -A3
$ kubectl delete job hello                # deletes its pods too (cascade)

CronJob

apiVersion: batch/v1
kind: CronJob
metadata:
  name: nightly-report
spec:
  schedule: "30 2 * * *"            # 02:30 every day, in the controller-manager's timezone (UTC usually)
  timeZone: "Europe/Berlin"         # 1.27+: explicit zone
  concurrencyPolicy: Forbid         # Allow (default) · Forbid (skip if previous still running) · Replace (kill previous)
  startingDeadlineSeconds: 300      # if it could not start within 5 min of schedule, skip this run
  successfulJobsHistoryLimit: 3     # keep last 3 successful Jobs (default 3)
  failedJobsHistoryLimit: 1         # default 1
  suspend: false                    # true pauses scheduling
  jobTemplate:
    spec:
      backoffLimit: 2
      ttlSecondsAfterFinished: 86400
      template:
        spec:
          restartPolicy: Never
          containers:
          - name: report
            image: myreporter:2.0
┌───────────── minute (0–59)
│ ┌─────────── hour (0–23)
│ │ ┌───────── day of month (1–31)
│ │ │ ┌─────── month (1–12)
│ │ │ │ ┌───── day of week (0–6, Sunday=0)
* * * * *
*/15 * * * *      every 15 minutes
0 */6 * * *       every 6 hours
0 9 * * 1-5       09:00 on weekdays
@hourly @daily @weekly @monthly     also accepted
$ kubectl create cronjob backup --image=busybox --schedule="*/5 * * * *" -- sh -c 'date; echo backup'
$ kubectl get cj                                   # SCHEDULE SUSPEND ACTIVE LAST SCHEDULE
$ kubectl create job backup-now --from=cronjob/backup   # run it immediately
$ kubectl get jobs -l ... ; kubectl logs job/backup-now
$ kubectl patch cj backup -p '{"spec":{"suspend":true}}'   # pause
CronJob gotchas
  • The CronJob controller checks every 10 s; a Job is created at most once per schedule slot. If a run is missed more than 100 times in a row (controller down, startingDeadlineSeconds unset), the CronJob stops scheduling and logs an error — set startingDeadlineSeconds.
  • Jobs may occasionally run twice (at-least-once semantics). Make them idempotent.
  • concurrencyPolicy: Forbid is what you want for "the 2 a.m. job must not overlap yesterday's slow one".
  • A Job's Pod template is immutable; changing the CronJob only affects future Jobs.
Under the hood · Linux

A DaemonSet is the cluster-wide equivalent of a systemd unit enabled on every host — and the node components that are not DaemonSets (kubelet, containerd) are precisely the ones systemd must start before any Pod can exist. Jobs and CronJobs are the successor to cron: instead of a crontab line on one machine (single point of failure, no retries, logs in local mail), you get a scheduled controller, retries with back-off, history, and logs in kubectl logs. The exit-code convention is the same one the shell uses — 0 is success, anything else counts as a failure toward backoffLimit.

CKA exam tip
  • There is no kubectl create daemonset. Generate a Deployment, change kind, delete replicas and strategy.
  • kubectl create job/cronjob exist; add completions, parallelism, backoffLimit by editing the YAML. Remember restartPolicy must be Never or OnFailure.
  • DaemonSet Pod missing on one node → check that node's taints vs the DaemonSet's tolerations, and nodeSelector.
  • "Run the CronJob now" → kubectl create job x --from=cronjob/y.

Hands-on lab (20 min)

# DaemonSet
$ kubectl create deploy agent --image=busybox $do -- sleep 3600 | sed 's/Deployment/DaemonSet/;/replicas/d;/strategy/d' | kubectl apply -f -
$ kubectl get ds agent; kubectl get pods -l app=agent -o wide      # one per worker (control-plane tainted)
$ kubectl patch ds agent --type=json -p '[{"op":"add","path":"/spec/template/spec/tolerations","value":[{"key":"node-role.kubernetes.io/control-plane","operator":"Exists"}]}]'
$ kubectl get pods -l app=agent -o wide                             # now on the control plane too
# Job with retries
$ kubectl create job flaky --image=busybox $do -- sh -c 'exit 1' | sed '/spec:/a\  backoffLimit: 2' | kubectl apply -f -
$ kubectl get pods -l job-name=flaky -w                             # a few pods, then Job Failed
$ kubectl describe job flaky | grep -A2 -E 'Conditions|BackoffLimitExceeded'
# parallel indexed job
$ kubectl create job shards --image=busybox $do -- sh -c 'echo shard $JOB_COMPLETION_INDEX; sleep 5' | sed '/spec:/a\  completions: 4\n  parallelism: 2\n  completionMode: Indexed' | kubectl apply -f -
$ kubectl get pods -l job-name=shards -w; kubectl logs -l job-name=shards --prefix
# CronJob
$ kubectl create cronjob tick --image=busybox --schedule="*/1 * * * *" -- date
$ sleep 70; kubectl get jobs; kubectl logs -l job-name --tail=1
$ kubectl create job tick-now --from=cronjob/tick && kubectl logs job/tick-now
$ kubectl delete ds agent; kubectl delete job flaky shards tick-now; kubectl delete cj tick

Key takeaways

  • DaemonSet = one Pod per matching node; tolerate the control-plane taint to include masters; updates roll node by node.
  • Job = run to completion with completions/parallelism/backoffLimit; restartPolicy must be OnFailure or Never; ttlSecondsAfterFinished cleans up.
  • CronJob = Jobs on a cron schedule; set concurrencyPolicy and startingDeadlineSeconds; runs are at-least-once.
  • kubectl create job --from=cronjob/x to trigger manually; suspend to pause.
