Every kubectl get is a JSON document; -o wide and describe are just two views of it. JSONPath lets you pick any field, iterate lists, filter by condition and format the result — which is how you answer "which node is each Pod on", "list every image in the cluster", "which PVs are Released", or produce exactly the file an exam task asks for. Together with --sort-by and custom-columns, it turns kubectl into a query tool; where it runs out, jq takes over.

What you'll learn

  • Reading the JSON first: -o json / -o yaml and the .items[] envelope
  • JSONPath syntax: paths, [*], range/end, filters [?(@…)], escaping
  • -o custom-columns and --sort-by for tables
  • Field selectors and label selectors vs JSONPath filters
  • When to switch to jq / yq, with equivalents

Step 0: look at the JSON

$ kubectl get pod web -o json | head -30              # metadata, spec, status
$ kubectl get pods -o json | jq '.items | length'      # a LIST: the pods are under .items[]
$ kubectl get pod web -o yaml | grep -n nodeName       # find the path you want, then express it

Single object: paths start at the root (.metadata.name). A list (get pods, no name): paths start with .items[*]. Forgetting .items is the most common empty result.

JSONPath syntax

ExpressionMeaningExample
{.a.b}Field access{.metadata.name}
{.items[*].x}Every element's x, space-separated{.items[*].metadata.name}
{.items[0]} / {.items[-1:]}Index / slice{.items[0].spec.nodeName}
{range .items[*]}…{end}Loop with a template per element{range .items[*]}{.metadata.name}{"\t"}{.spec.nodeName}{"\n"}{end}
{"\n"}, {"\t"}, {" "}Literal text inside the templateseparators
[?(@.x=="y")]Filter elements by a condition on the current element @{.items[?(@.status.phase=="Running")].metadata.name}
[?(@.type=="Ready")]Filter inside a nested list{.status.conditions[?(@.type=="Ready")].status}
{.metadata.labels.app}Map keylabels, annotations
{.metadata.labels.app\.kubernetes\.io/name}Escape dots in keys with \.also {.data.tls\.crt}
{..name}Recursive descent (every name at any depth) — rarely what you want
{@}The current object{range .items[*]}{@.metadata.name}

kubectl's JSONPath is Kubernetes' own implementation: no arithmetic, no functions, comparisons limited to ==, !=, <, >, and &&/|| unsupported in most versions. Wrap the whole expression in single quotes on the shell to protect $, *, @, and quotes.

Worked examples

# names only
$ kubectl get pods -o jsonpath='{.items[*].metadata.name}'; echo
# pod → node, one per line
$ kubectl get pods -A -o jsonpath='{range .items[*]}{.metadata.namespace}{"/"}{.metadata.name}{"\t"}{.spec.nodeName}{"\n"}{end}'
# every image running in the cluster, unique
$ kubectl get pods -A -o jsonpath='{.items[*].spec.containers[*].image}' | tr ' ' '\n' | sort -u
# node internal IPs
$ kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.addresses[?(@.type=="InternalIP")].address}{"\n"}{end}'
# nodes that are Ready
$ kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.conditions[?(@.type=="Ready")].status}{"\n"}{end}'
# PVs by capacity — no arithmetic in jsonpath, so sort with --sort-by
$ kubectl get pv --sort-by=.spec.capacity.storage -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.capacity.storage}{"\t"}{.status.phase}{"\n"}{end}'
# the one field you need in a script
$ TOKEN=$(kubectl get secret sa-token -o jsonpath='{.data.token}' | base64 -d)
$ NODEPORT=$(kubectl get svc web -o jsonpath='{.spec.ports[0].nodePort}')
$ kubectl get pod web -o jsonpath='{.status.containerStatuses[0].lastState.terminated.reason}'   # OOMKilled?
# context / kubeconfig fields
$ kubectl config view -o jsonpath='{.contexts[*].name}'
$ kubectl config view -o jsonpath='{.contexts[?(@.name=="prod")].context.user}'
# write to a file as an exam task might demand
$ kubectl get nodes -o jsonpath='{.items[*].status.nodeInfo.osImage}' > /opt/outputs/os.txt

custom-columns and sort-by

$ kubectl get pods -o custom-columns='NAME:.metadata.name,NODE:.spec.nodeName,IP:.status.podIP,IMAGE:.spec.containers[0].image'
$ kubectl get pods -o custom-columns='NAME:.metadata.name,READY:.status.conditions[?(@.type=="Ready")].status,RESTARTS:.status.containerStatuses[0].restartCount'
$ kubectl get pv -o custom-columns='NAME:.metadata.name,CAP:.spec.capacity.storage,CLAIM:.spec.claimRef.name' --sort-by=.spec.capacity.storage
$ kubectl get pods -A --sort-by=.metadata.creationTimestamp | tail -5      # newest pods
$ kubectl get events --sort-by=.lastTimestamp
$ kubectl get pods -o custom-columns-file=cols.txt                          # reusable column definitions

custom-columns uses the same path syntax without the outer braces and applies per item automatically (no range). --sort-by takes one path; it sorts numerically for numbers and quantities, lexically otherwise. --no-headers for scripts.

Selectors: filter on the server

$ kubectl get pods --field-selector status.phase=Running,spec.nodeName=worker-1     # only a few fields supported: metadata.name/namespace, status.phase, spec.nodeName, spec.restartPolicy…
$ kubectl get events --field-selector type=Warning,involvedObject.kind=Pod
$ kubectl get pods -l app=web,tier!=cache
$ kubectl get pods -l 'env in (dev,staging)' --show-labels

Field and label selectors are evaluated by the API server (cheap, works with -w); JSONPath filters are evaluated by kubectl after fetching everything. Prefer selectors when they can express the condition.

When JSONPath runs out: jq and yq

$ kubectl get pods -A -o json | jq -r '.items[] | select(.status.containerStatuses[]?.restartCount > 3) | "\(.metadata.namespace)/\(.metadata.name)"'
$ kubectl get pods -o json | jq -r '.items[] | [.metadata.name, (.spec.containers | length)] | @tsv'
$ kubectl get nodes -o json | jq '[.items[].status.allocatable.cpu] '           # arrays, math, grouping — jq has it all
$ kubectl get pods -o json | jq -r '.items[] | select(.spec.containers[].resources.limits == null) | .metadata.name'   # pods without limits
$ kubectl get deploy web -o yaml | yq '.spec.template.spec.containers[0].image'
$ kubectl get cm app -o yaml | yq '.data."app.yaml"'                            # yq (mikefarah) for YAML, same idea

Under the hood · Linux

kubectl fetches the JSON over HTTPS and applies the template client-side — you can see the raw document with kubectl get --raw /api/v1/pods | jq .. Everything after that is text processing, and the Unix toolbox composes: | tr ' ' '\n' | sort | uniq -c | sort -rn for histograms, | column -t for alignment, | tee file to save and see, | xargs -n1 kubectl delete pod to act on the result. The shell toolkit page covers jq/yq/awk in depth.

CKA exam tip
  • Exam wording: "list … and save to /opt/x.txt" — use -o jsonpath or custom-columns, redirect, then cat the file to check. Match the requested format exactly (one per line? sorted?).
  • "Sorted by X" → --sort-by=.path. It is available on get for any resource.
  • Always echo after a jsonpath command — no trailing newline is emitted; add {"\n"} in templates.
  • jq is usually installed on exam nodes, but do not depend on it: know range/end and [?()].
  • Find paths quickly with kubectl get X -o yaml | grep -n field or kubectl explain X.spec.field.

Hands-on lab (15 min)

$ kubectl create deploy web --image=nginx:1.26 --replicas=3 && kubectl create deploy api --image=nginx:1.27 --replicas=2
$ kubectl get pods -o jsonpath='{.items[*].metadata.name}'; echo
$ kubectl get pods -o jsonpath='{range .items[*]}{.metadata.name}{" → "}{.spec.nodeName}{"\n"}{end}'
$ kubectl get pods -o jsonpath='{.items[?(@.metadata.labels.app=="api")].spec.containers[0].image}'; echo
$ kubectl get pods -o custom-columns='POD:.metadata.name,IMAGE:.spec.containers[0].image,NODE:.spec.nodeName' --sort-by=.spec.nodeName
$ kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.capacity.cpu}{" cpu\t"}{.status.nodeInfo.kubeletVersion}{"\n"}{end}' | column -t
$ kubectl get pods -o json | jq -r '.items[] | "\(.metadata.name) \(.status.podIP)"'
$ kubectl get pods -o jsonpath='{.items[*].spec.containers[*].image}' | tr ' ' '\n' | sort | uniq -c
$ kubectl delete deploy web api

Key takeaways

  • Look at -o json first; lists live under .items[].
  • JSONPath: {.path}, [*], range…end with {"\n"}, filters [?(@.x=="y")], escape dots in keys.
  • custom-columns for tables, --sort-by for order, field/label selectors for server-side filtering.
  • No math or counting in JSONPath — pipe to jq/yq/sort/uniq.
