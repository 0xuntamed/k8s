An Operator is a CRD plus a controller: a program running in the cluster that watches your custom resources and does whatever a human operator would do to make reality match them — create a StatefulSet, run a backup, fail over a primary, rotate a certificate. It uses the exact same watch-and-reconcile pattern as the built-in controllers from Day 6; the only difference is that you (or a vendor) wrote the reconcile function. This lesson explains the pattern, runs a real operator, and shows what a reconcile loop looks like in code.

The controller pattern, again

A controller keeps an informer — a cached, watched view of the objects it cares about. Every change (and periodic resyncs) puts the object's key (namespace/name) on a work queue. A worker pops a key and calls Reconcile(key), which:

  1. Reads the current object (the desired state) — and if it is gone, cleans up.
  2. Reads the current world (the StatefulSets, Secrets, Services it manages).
  3. Computes the difference and makes the minimal API calls to close it.
  4. Updates status to report what it observed.
  5. Returns; if anything failed, the key is re-queued with back-off.
Level-triggered and idempotent

Reconcile does not receive "what changed" — only "look at this object". It must reach the correct end state from any starting point, and running it twice must change nothing the second time. This is why controllers survive restarts, missed events and partial failures: the next reconcile simply looks again. It is also why writing one is mostly about reading state carefully, not reacting to events.

The conventions that make operators well-behaved

ownerReferences
Every child object (StatefulSet, Service) carries a reference to the CR that created it. Delete the CR → garbage collector deletes the children. kubectl get sts -o jsonpath='{.items[*].metadata.ownerReferences}'.
status + conditions
Written only by the controller, via the /status subresource. status.conditions[] with type/status/reason/message/lastTransitionTime (e.g. Ready=True) is the standard shape; kubectl wait --for=condition=Ready db/orders works with it.
finalizers
A string the controller adds to metadata.finalizers. Deleting the CR then only sets deletionTimestamp; the controller sees it, does external cleanup (delete the cloud disk, deregister from DNS), removes its finalizer, and only then is the object gone. A stuck Terminating object means the controller that owns the finalizer is not running.
Leader election
Operators run 1–3 replicas; a Lease object elects one active reconciler so two replicas never fight.
RBAC
The operator's ServiceAccount needs a ClusterRole for its CRD (all verbs), for the child types it manages, and for events and leases. Least privilege matters: an operator that can create Pods cluster-wide is a powerful thing.
Events
Controllers emit Events on the CR (kubectl describe db orders) — the first place to look when a CR is not progressing.

A real operator: cert-manager

$ kubectl apply -f https://github.com/cert-manager/cert-manager/releases/latest/download/cert-manager.yaml
$ kubectl get crds | grep cert-manager.io          # certificates, issuers, clusterissuers, certificaterequests, orders, challenges
$ kubectl -n cert-manager get deploy,sa,pods       # the controller, its webhook, its cainjector
$ kubectl get clusterrole cert-manager-controller-certificates -o yaml | head -30   # what it may touch
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: selfsigned
spec:
  selfSigned: {}
---
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: web-tls
  namespace: default
spec:
  secretName: web-tls                 # the operator will CREATE this Secret
  dnsNames: [web.example.internal]
  duration: 2160h                     # 90 days
  renewBefore: 360h                   # renew 15 days before expiry — forever
  issuerRef: {name: selfsigned, kind: ClusterIssuer}
$ kubectl apply -f cert.yaml
$ kubectl get certificate web-tls                  # READY True after a few seconds
$ kubectl get secret web-tls -o jsonpath='{.data.tls\.crt}' | base64 -d | openssl x509 -noout -subject -dates
$ kubectl get secret web-tls -o jsonpath='{.metadata.ownerReferences[0].kind}'    # Certificate — owned
$ kubectl describe certificate web-tls | tail -8   # Events: Issuing, Generated, Requested, Issued
$ kubectl delete secret web-tls; sleep 5; kubectl get secret web-tls     # it is back: reconcile restored desired state

That last line is the whole point. You declared "a valid certificate for this name must exist in this Secret"; the operator creates it, renews it before expiry, and re-creates it if deleted. A human operator's runbook — "check expiry monthly, regenerate, update the Secret, restart the pods" — became a controller.

Anatomy of an operator deployment

# typical manifest bundle (what Helm charts / OLM install)
CustomResourceDefinition   databases.stable.example.com
Namespace                  db-operator-system
ServiceAccount             db-operator
ClusterRole                db-operator     # databases/*; statefulsets, services, secrets, pvcs: CRUD; events: create; leases: CRUD
ClusterRoleBinding         db-operator
Deployment                 db-operator     # 1–2 replicas, image with the controller binary, --leader-elect
Service                    db-operator-metrics   # /metrics for Prometheus
(optional) ValidatingWebhookConfiguration for the CRD

OLM (Operator Lifecycle Manager, OperatorHub.io) packages these with upgrade channels for OpenShift-style clusters; most other clusters install operators with Helm (Day 43).

Writing one

kubebuilder and Operator SDK (Go), kopf (Python) and Java Operator SDK generate the CRD, RBAC, main loop and a Reconcile stub from a type definition. Your job is the middle of this function:

func (r *DatabaseReconciler) Reconcile(ctx context.Context, req ctrl.Request) (ctrl.Result, error) {
    var db stablev1.Database
    if err := r.Get(ctx, req.NamespacedName, &db); err != nil {
        return ctrl.Result{}, client.IgnoreNotFound(err)      // deleted: children are GC'd via ownerRefs
    }
    // 1. desired child: a StatefulSet derived from db.Spec
    desired := buildStatefulSet(&db)
    ctrl.SetControllerReference(&db, desired, r.Scheme)      // ownerReference

    // 2. observe + act: create if missing, patch if different
    var current appsv1.StatefulSet
    err := r.Get(ctx, client.ObjectKeyFromObject(desired), &current)
    switch {
    case apierrors.IsNotFound(err):
        if err := r.Create(ctx, desired); err != nil { return ctrl.Result{}, err }
    case err != nil:
        return ctrl.Result{}, err
    case !equality.Semantic.DeepEqual(current.Spec.Replicas, desired.Spec.Replicas):
        current.Spec.Replicas = desired.Spec.Replicas
        if err := r.Update(ctx, &current); err != nil { return ctrl.Result{}, err }
    }

    // 3. report
    db.Status.Phase = phaseFrom(&current)
    if err := r.Status().Update(ctx, &db); err != nil { return ctrl.Result{}, err }
    return ctrl.Result{RequeueAfter: 5 * time.Minute}, nil   // periodic re-check
}

func (r *DatabaseReconciler) SetupWithManager(mgr ctrl.Manager) error {
    return ctrl.NewControllerManagedBy(mgr).
        For(&stablev1.Database{}).          // watch our CRs
        Owns(&appsv1.StatefulSet{}).         // and re-reconcile when a child changes
        Complete(r)
}

Notice: no event types, no "on create / on update" branches. Read, compare, act, report. The framework handles caching, queues, retries, leader election and metrics.

Platform

CKA exam tip
  • You will not write an operator, but you will use one: install from a URL/Helm, create a CR from its docs, check kubectl get <kind> READY/STATUS columns and describe events.
  • CR stuck with no status → is the operator Pod running? kubectl -n <op-ns> logs deploy/<operator> — RBAC errors ("forbidden") are the classic cause.
  • Object stuck Terminating → a finalizer whose controller is gone. Fix the controller or remove the finalizer.

Key takeaways

  • Operator = CRD + controller. The controller watches CRs and reconciles: read desired, read actual, act minimally, write status, requeue.
  • Reconcile is level-triggered and idempotent — it must work from any state and be safe to repeat.
  • Conventions: ownerReferences (GC), status/conditions (reporting), finalizers (cleanup before deletion), leader election, least-privilege RBAC, Events.
  • cert-manager, Prometheus Operator, database operators and Argo CD are controllers of this exact shape; you operate them by creating CRs and reading their status.
