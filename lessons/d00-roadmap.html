Kubernetes has a reputation for being hard. Most of that difficulty is vocabulary and layering: dozens of nouns that all depend on each other. This course removes the difficulty by teaching the layers in order — containers first, then the cluster, then everything that runs on it — and these notes go one layer lower still, to the Linux features that make each Kubernetes idea real.

This page covers

  • What the CKA exam actually tests, and how the 60 lessons map to it
  • How each lesson page on this site is structured
  • A realistic study schedule and the lab environment you need

What the CKA is

The Certified Kubernetes Administrator (CKA) is a 2-hour, hands-on, terminal-only exam from the Linux Foundation / CNCF. There are no multiple-choice questions: you get SSH access to several real clusters and 15–20 tasks such as "create a Deployment with three replicas exposed on NodePort 30080", "the worker node is NotReady — fix it", or "upgrade the control plane to version X". You pass at 66%.

CKA exam tip

The exam is open-book for kubernetes.io/docs only. Speed comes from knowing the shape of every YAML object and generating skeletons with kubectl ... --dry-run=client -o yaml, not from memorising fields. Every lesson here shows the imperative shortcut next to the declarative manifest for that reason.

The road, module by module

  1. Containers & Docker (Days 1–5) Images, layers, Dockerfiles, CMD vs ENTRYPOINT, multi-stage builds. Kubernetes runs containers; if a container is a mystery, everything above it is too. The Linux track's Namespaces, cgroups and OverlayFS pages belong here.
  2. Kubernetes Core (Days 6–10) Why orchestration exists, the control-plane components, a local KIND cluster, YAML, ReplicaSets and Deployments.
  3. Services, Networking Basics & Namespaces (Days 11–14) How traffic reaches Pods and how a cluster is carved up.
  4. Scheduling & Resources (Days 15–20) Where Pods land and why; CPU/memory accounting; autoscaling.
  5. Pod Design & Lifecycle (Days 21–23) Multi-container patterns, what "restart" and "terminate" really mean, probes.
  6. Storage (Days 24–27) Volumes from Docker to CSI-backed PersistentVolumes.
  7. Configuration & Workload Controllers (Days 28–29) ConfigMaps, Secrets, DaemonSets, Jobs, CronJobs.
  8. Security (Days 30–38) The longest module: encryption from scratch, TLS, the PKI every cluster carries, kubeconfig, RBAC, ServiceAccounts, admission control.
  9. Extending & Packaging (Days 39–43) CRDs, Operators, Pod security, Kustomize, Helm.
  10. Advanced Workloads (Days 44–46) StatefulSets, private registries, priority and preemption.
  11. Networking Deep Dive (Days 47–53) NetworkPolicies, DNS/CoreDNS, Ingress on AWS, Gateway API.
  12. Cluster Operations (Days 54–59) kubeadm install and upgrade, monitoring, control-plane and node troubleshooting, JSONPath.

Lab environment

You need three things, all free:

  • Docker Desktop (or Docker Engine on Linux) for Days 1–5 and for KIND.
  • KIND ("Kubernetes in Docker") from Day 8 onward — a real multi-node cluster in seconds, thrown away just as fast.
  • Two or three VMs (VirtualBox/Multipass locally, or small cloud instances) for the kubeadm lessons in Module 12. Days 44 and 50–51 use Amazon EKS for realism; the concepts transfer to any cloud and the notes say what is cloud-specific.
Tip

Also bookmark killercoda.com playgrounds and the official killer.sh simulator (two sessions are included with the exam registration). Use them for the troubleshooting module — breaking a real control plane is the only way to learn to fix one.

Key takeaways

  • CKA is performance-based: practise in a terminal, not with flashcards.
  • The course teaches bottom-up — containers → cluster → workloads → networking → security → operations. Follow the order the first time.
  • When something feels like magic, it is a Linux feature you have not met yet. Follow the orange box.
