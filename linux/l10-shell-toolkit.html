kubectl prints text; nodes speak files, sockets and processes. The gap is closed by two dozen Unix commands that have not changed in decades. This is the working set — organised by the question you are asking, with the exact flags that matter during an incident or an exam — plus the shell habits that make you fast: pipes, substitution, loops, and knowing which tool is installed where.

What you'll learn

  • Text: grep, awk, sed, cut, sort, uniq, tr, head/tail, wc, column, diff
  • Structured data: jq, yq, base64
  • Files and disk: find, du, df, lsof, tar, stat
  • Processes and resources: ps, top, free, vmstat, strace, dmesg
  • Network: ss, curl, nc, dig, tcpdump, ip
  • Shell glue: pipes, $(…), <(…), loops, xargs, tee, watch, timeout, heredocs

Structured data

# jq — JSON
$ kubectl get pods -o json | jq '.items[] | {name: .metadata.name, node: .spec.nodeName, phase: .status.phase}'
$ kubectl get pods -o json | jq -r '.items[] | select(.status.phase != "Running") | .metadata.name'      # -r: raw strings, no quotes
$ kubectl get nodes -o json | jq -r '.items[] | "\(.metadata.name)\t\(.status.allocatable.cpu)\t\(.status.allocatable.memory)"'
$ kubectl get pods -A -o json | jq '[.items[].status.containerStatuses[]?.restartCount] | add'         # total restarts
$ kubectl get pods -o json | jq -r '.items[] | select(.spec.containers[].resources.limits == null) | .metadata.name' | sort -u
$ cat /etc/containerd/config.toml | grep -A2 runc.options   # (TOML: no jq; grep)
$ echo '{"a":{"b":[1,2]}}' | jq '.a.b[1]'; jq -c . file.json    # -c compact; jq keys; jq 'to_entries'; jq -s 'add' (slurp files)
# yq (mikefarah) — YAML, same syntax
$ yq '.spec.template.spec.containers[0].image' deploy.yaml
$ yq -i '.spec.replicas = 3' deploy.yaml                          # edit in place
$ kubectl get cm coredns -n kube-system -o yaml | yq '.data.Corefile'
$ yq eval-all 'select(.kind == "Deployment")' all.yaml           # filter multi-doc
$ yq -o json deploy.yaml | jq .                                  # YAML → JSON
# base64
$ echo -n 'p@ss' | base64; echo cEBzcw== | base64 -d; base64 -w0 file   # -w0: no line wraps (needed for CSR requests)

Files and disk

$ df -h; df -h /var/lib/containerd /var/log                  # filesystem usage — what DiskPressure looks at
$ du -xsh /var/log/pods/* | sort -h | tail -5                 # who is big (-x: one filesystem)
$ find /var/log -name '*.log' -size +100M -mtime -1           # big, recent
$ find /var/lib/kubelet/pods -maxdepth 1 -type d -mmin -10    # pod dirs changed in the last 10 min
$ find / -xdev -type f -size +500M 2>/dev/null
$ lsof +L1                                                    # deleted-but-open files (df vs du mismatch)

Processes and resources

$ ps -eo pid,ppid,user,stat,etime,rss,cmd --sort=-rss | head        # by memory
$ ps -eo pid,stat,cmd | awk '$2 ~ /Z/'                              # zombies
$ pgrep -a kubelet; pidof containerd; pkill -f 'sleep 3600'
$ top -o %MEM -n1 -b | head -15; htop
$ free -m; cat /proc/meminfo | head -5; vmstat 1 5                  # memory, swap, run queue, iowait
$ uptime; nproc; cat /proc/loadavg
$ dmesg -T | tail -30; dmesg -T | grep -iE 'oom|killed|error|nf_conntrack'
$ strace -p $(pidof kubelet) -f -e trace=openat -o /tmp/kl.trace & sleep 5; kill %1; grep -c ENOENT /tmp/kl.trace   # what files is it failing to open?
$ strace -f -e trace=network curl -s http://api:8080 2>&1 | grep -E 'connect|sendto' | head
$ cat /proc/$(pidof kubelet)/limits | grep files; ulimit -n
$ iostat -xz 1 3 2>/dev/null || cat /proc/diskstats | head    # disk latency (etcd cares)

Network

$ ss -tlnp                                   # listening TCP + process; -u UDP; -a all; -4/-6
$ ss -tnp state established '( dport = :6443 )'   # who is connected to the API server
$ ss -s                                      # socket summary; conntrack pressure hints
$ ip -br addr; ip route; ip route get 10.244.2.9; ip neigh; ip -s link show eth0
$ curl -sS -o /dev/null -w '%{http_code} %{time_total}s\n' http://api:8080/health     # status + timing
$ curl -sk https://10.0.0.10:6443/healthz; curl -v --cacert ca.crt https://host:6443/version
$ curl -H 'Host: shop.local' http://localhost/; curl --resolve shop.local:443:127.0.0.1 -k https://shop.local/
$ nc -zv db 5432; nc -zvu 10.96.0.10 53; timeout 2 bash -c '</dev/tcp/db/5432' && echo open    # the last needs no tools
$ dig +short svc.ns.svc.cluster.local; dig @10.96.0.10 x; nslookup x; getent hosts x
$ sudo tcpdump -i any -nn port 53 -c 20; sudo tcpdump -i eth0 -nn 'tcp port 6443 and tcp[tcpflags] & tcp-syn != 0'
$ sudo tcpdump -i any -nn host 10.244.2.9 -w /tmp/cap.pcap        # capture for Wireshark
$ traceroute -n 8.8.8.8; mtr -n -r -c 5 8.8.8.8
$ sudo iptables -t nat -S | grep 10.96.0.42; sudo conntrack -L | grep 10.96.0.42
$ sudo nsenter -t $(crictl inspect $CID | jq .info.pid) -n ss -tlnp   # inside a pod's netns with host tools

Hands-on lab (15 min)

$ kubectl create deploy web --image=nginx --replicas=3 && kubectl create deploy bad --image=nginx:nope
$ kubectl get pods | awk 'NR>1 && $3 != "Running" {print $1, $3}'
$ kubectl get pods -o json | jq -r '.items[] | select(.status.phase != "Running") | .metadata.name'
$ kubectl get pods -o jsonpath='{.items[*].spec.containers[*].image}' | tr ' ' '\n' | sort | uniq -c | sort -rn
$ for p in $(kubectl get pods -l app=web -o name); do echo "$p: $(kubectl get $p -o jsonpath='{.spec.nodeName}')"; done
$ kubectl get pods -l app=web -o name | xargs -n1 -I{} sh -c 'kubectl exec {} -- hostname'
$ kubectl get events --sort-by=.lastTimestamp | grep -i pull | tail -3
$ diff <(kubectl get deploy web -o yaml | yq '.spec.template.spec.containers[0]') <(kubectl get deploy bad -o yaml | yq '.spec.template.spec.containers[0]')
$ watch -n1 -d 'kubectl get pods; echo; kubectl top pods 2>/dev/null' &   # Ctrl-C after a look
$ kubectl run t --rm -it --image=nicolaka/netshoot -- sh -c 'ss -tlnp; dig +short kubernetes.default.svc.cluster.local; curl -sS -o /dev/null -w "%{http_code}\n" http://web'
$ kubectl delete deploy web bad

Key takeaways

  • Text: grep to find, awk to pick columns and filter, sed to edit, sort|uniq -c for histograms, diff with process substitution to compare.
  • jq for JSON (-r, select, string interpolation), yq for YAML (same syntax, -i to edit).
  • Disk: df (filesystem) vs du (files) vs lsof +L1 (deleted-open). Processes: ps --sort, dmesg for OOM, strace for "what file/socket is it failing on".
  • Network: ss for sockets, ip for interfaces/routes, curl -w for status+timing, nc/bash /dev/tcp for reachability, dig for DNS, tcpdump for truth, nsenter -n to do all of it inside a Pod.
  • Glue: pipes, $( ), <( ), loops, xargs, tee, watch, timeout — and know which tools each image actually has.
