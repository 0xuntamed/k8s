Image layers, the container's writable layer, emptyDir, hostPath, a PersistentVolume, a ConfigMap file, the Secret tmpfs — every one of them is a mount in a container's mount namespace. This page covers the mount table, bind mounts and tmpfs, and then OverlayFS, the union filesystem that turns a stack of read-only layers into one writable root without copying anything.

What you'll learn

  • The mount table: mount, findmnt, /proc/self/mountinfo, mount namespaces
  • Bind mounts (a directory at a second path), tmpfs (RAM), read-only remounts, propagation
  • OverlayFS: lowerdir/upperdir/workdir/merged, copy-up, whiteouts
  • How containerd stores images and containers on disk (/var/lib/containerd)
  • Disk accounting: df vs du, where node disk goes, and DiskPressure

The mount table

A Linux filesystem tree is assembled at runtime by mounting filesystems onto directories. The kernel keeps a per-mount-namespace table; a process in a new mount namespace starts with a copy of its parent's table and can change it without affecting anyone else. That is what gives a container its own /.

$ findmnt                                  # the tree, with source, fstype and options
$ findmnt /                                # what backs the root
$ findmnt -t overlay                       # every container rootfs on this node
$ cat /proc/self/mountinfo | head -5       # the raw table: mount id, parent, root, mount point, options, fstype, source
$ findmnt -N $(pgrep -o nginx)             # a container's view (its mount namespace) from the host
$ sudo mount -t tmpfs -o size=64m tmpfs /mnt/scratch     # RAM-backed
$ sudo mount --bind /srv/data /mnt/data                  # same directory, second path
$ sudo mount -o remount,ro,bind /mnt/data                # make that view read-only
$ sudo umount /mnt/data /mnt/scratch
bind mount
Exposes an existing directory (or file) at another path. No copy; same inodes. Docker -v /host:/ctr, every Kubernetes volume mount into a container, and CSI's "publish" step are bind mounts.
tmpfs
A filesystem in page cache/RAM (may swap). emptyDir medium: Memory, Secret and ConfigMap volumes, /dev/shm. Counts against the cgroup's memory.
propagation
private (default for containers: new mounts under it are invisible outside), rslave (see host mounts appear), rshared (both ways). Kubernetes mountPropagation: HostToContainer|Bidirectional; needed by CSI node plugins that mount on behalf of the host.
read-only
readOnly: true on a volumeMount = a read-only bind mount; readOnlyRootFilesystem = the overlay root remounted read-only.

OverlayFS

$ mkdir -p /tmp/ov/{lower1,lower2,upper,work,merged}
$ echo "from layer 1" > /tmp/ov/lower1/a.txt; echo "from layer 2" > /tmp/ov/lower2/b.txt; echo "layer1 version" > /tmp/ov/lower1/c.txt; echo "layer2 version" > /tmp/ov/lower2/c.txt
$ sudo mount -t overlay overlay -o lowerdir=/tmp/ov/lower2:/tmp/ov/lower1,upperdir=/tmp/ov/upper,workdir=/tmp/ov/work /tmp/ov/merged
$ ls /tmp/ov/merged                        # a.txt b.txt c.txt — the union
$ cat /tmp/ov/merged/c.txt                 # "layer2 version" — leftmost lowerdir wins
$ echo "changed" >> /tmp/ov/merged/a.txt   # write → COPY-UP: a.txt is copied to upper, then modified there
$ ls /tmp/ov/upper                         # a.txt (the modified copy); lower1/a.txt is untouched
$ rm /tmp/ov/merged/b.txt                  # delete → a WHITEOUT in upper hides it
$ ls -l /tmp/ov/upper                      # c--------- b.txt  (character device 0/0 = whiteout)
$ ls /tmp/ov/merged                        # a.txt c.txt — b.txt is hidden, still present in lower2
$ sudo umount /tmp/ov/merged
lowerdir
One or more read-only layers, colon-separated, rightmost is the bottom. The image layers.
upperdir
The single writable layer: every write, new file and deletion marker lands here. The container layer. Delete the container = delete this directory.
workdir
Scratch space overlayfs needs for atomic operations; same filesystem as upper.
merged
The union view: what the container sees as /.
copy-up
First write to a file from a lower layer copies the whole file to upper. Writing one byte to a 1 GB file in a lower layer copies 1 GB — why databases and logs must not live in the container layer.
whiteout
A 0/0 character device in upper marks a lower file as deleted; an opaque xattr on a directory hides everything below. Deleting files in a later image layer does not shrink the image (Day 5).

How containerd stores it

$ sudo ls /var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/    # numbered dirs: one per layer AND per container
$ sudo ls /var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/42/fs   # a layer's files
$ sudo ctr -n k8s.io snapshots ls | head          # KEY (digest or container id) PARENT KIND (Committed = layer, Active = container)
$ sudo ctr -n k8s.io content ls | head            # the compressed blobs as pulled (deleted after unpack unless kept)
$ findmnt -t overlay | head -3                    # each running container = one overlay mount:
# lowerdir=/var/lib/containerd/…/snapshots/38/fs:/…/37/fs:/…/36/fs,upperdir=/…/snapshots/42/fs,workdir=/…/42/work
$ sudo crictl imagefsinfo                         # bytes used by images
$ sudo du -sh /var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots/* | sort -h | tail

Pull = download blobs → unpack each into a snapshot whose parent is the previous layer. Run = create an active snapshot (empty upper) on top of the image's top layer and mount the overlay. Ten Pods from one image share every lower snapshot; each has its own tiny upper. kubectl exec … df -h / inside a container reports the node's filesystem size and usage, because the overlay upper lives on it — a confusing but correct number.

Disk accounting and DiskPressure

$ df -h / /var/lib/containerd /var/lib/kubelet /var/log        # filesystem-level: what the kubelet watches (nodefs, imagefs)
$ sudo du -xsh /var/lib/containerd /var/lib/kubelet/pods /var/log/pods 2>/dev/null   # who is using it
$ sudo du -xsh /var/log/pods/* | sort -h | tail -5                                    # the log hog
$ sudo crictl rmi --prune                                       # unused images
$ sudo journalctl --vacuum-size=200M
$ kubectl describe node worker-1 | grep -A3 DiskPressure         # kubelet evicts when nodefs.available < 10% (default) or imagefs < 15%
$ kubectl get pod x -o jsonpath='{.spec.containers[0].resources.limits.ephemeral-storage}'   # per-container cap; exceeding evicts the Pod

df counts blocks the filesystem considers used (including deleted-but-open files — a rotated log still held by a process); du sums files it can see. A large gap between them means an unlinked open file: lsof +L1 or find /proc/*/fd -lname '*(deleted)'.

Hands-on lab (15 min)

# overlay by hand: run the OverlayFS block above, then observe copy-up cost
$ dd if=/dev/zero of=/tmp/ov/lower1/big bs=1M count=200 status=none
$ sudo mount -t overlay overlay -o lowerdir=/tmp/ov/lower1,upperdir=/tmp/ov/upper,workdir=/tmp/ov/work /tmp/ov/merged
$ du -sh /tmp/ov/upper; time sh -c 'echo x >> /tmp/ov/merged/big'; du -sh /tmp/ov/upper     # one byte → 200 MB copied
$ sudo umount /tmp/ov/merged
# a real container's mounts
$ docker run -d --name m -v $(pwd):/host:ro --tmpfs /scratch:size=16m nginx; PID=$(docker inspect -f '{{.State.Pid}}' m)
$ sudo findmnt -N $PID | grep -E ' / |/host|/scratch|/etc/(hosts|resolv)'      # overlay root, bind, tmpfs, and the kubelet-style /etc files
$ docker exec m df -h / /host /scratch
$ docker exec m sh -c 'echo hi > /newfile'; docker diff m                        # A /newfile — the upper dir
$ docker rm -f m

Key takeaways

  • A container's filesystem is a mount table in its own namespace: an overlay root plus bind/tmpfs mounts for every volume.
  • OverlayFS = read-only lowerdirs (image layers) + one upperdir (container writes) + a merged view; writes copy-up, deletes whiteout.
  • containerd keeps layers as snapshots shared by all containers; each container adds an active snapshot.
  • Writes outside a volume die with the container and count as ephemeral-storage; Secrets/ConfigMaps are tmpfs; PVCs are CSI mounts.
  • df/du/findmnt/crictl imagefsinfo explain DiskPressure.
